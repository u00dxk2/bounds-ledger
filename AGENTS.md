**Operating principles.** The portfolio's canonical operating principles live at `../skylark-site/docs/skylark-operating-principles.md` and apply here in full. The two that bite this lane most often: **David is never the distribution channel** — any "how do we get people to see this" answer is product-side share-worthiness, not founder outreach; and **ship obvious first-order improvements under authority** — data is for optimising, not for permitting. ## What this is

A reproducible, continuously re-verified ledger of drifting mathematical records (bounds / constants / certificates) that alarms when a cited record moves. Node stdlib + `fetch` only; `npm install` is a no-op. The repo is PUBLIC (since 2026-08-08).

**EVERY push to `main` PUBLISHES, doc-only commits included — this line used to say "Nothing deploys", which was TRUE until 2026-08-21 and false for the five days after (corrected 2026-08-26).** `10e1db3` turned Pages on that day and nothing swept the phrase; it then survived in this file, in today's cold-start primer, and in the 2026-07-29 engineering-health review's capability table. **That makes five for the rule that closing a gate must include a sweep for text that cited it** — and the reason it did not fire is that turning a surface **on** does not feel like closing a gate. It is one. GitHub Pages (`build_type: legacy`, source `main` at `/`) builds on every commit and serves `index.html` at `https://u00dxk2.github.io/bounds-ledger/`. So there are **two** automations, not one: the Actions drift job and the Pages build.

**Measured, not read off a config field** — the transferable rule from learn-the-dao's 2026-08-26 finding is that the deploys API is the only observable, so ask whether a build ROW exists for the commit: `gh api repos/u00dxk2/bounds-ledger/pages/builds`. It returned **30 consecutive rows, one per commit**, doc-only commits included. The positive control is unusually clean: `1b0f85e` touched only `CLAUDE.md`, `continuity/items.json` and a cold-start primer — no script, no `index.html` — and it produced a build row that **FAILED** (`Page build failed.`), the first error in those 30. A commit that supposedly could not deploy broke the deploy.

**THE PUBLISH IS NOT CI-GATED, AND THAT IS A STANDING FACT ABOUT THIS LANE, NOT AN OUTAGE ARTEFACT (measured 2026-08-26).** There is no Render service here and therefore no `autoDeployTrigger=checksPass` to fail open — GitHub Pages legacy builds fire on **push**, and wait for nothing. Timestamp pair that settles it, from a fully settled commit: the Pages build for `c25cecd` was created at **2026-08-25T23:06:53Z** and its CI run started at **23:06:55Z** — the publish was created **two seconds before CI began**. Corroborated during the outage: at HEAD there were **0 check-runs** while Pages still created a build for every commit (`gh api repos/OWNER/REPO/commits/<sha>/check-runs` → 0 today, **7** on the settled prior `c25cecd`, which is the negative control).

**What follows, and it nearly bit on the day it was measured:** `render-site --check` — the gate that catches a malformed `index.html` — runs in CI **in parallel with the publish, not before it**. On any ordinary day a bad page goes live and CI tells you afterwards. On 2026-08-26 commit `784e4f4` carried an `index.html` whose first 45 bytes had been clobbered; the only reason it never reached a visitor is that Pages was erroring in an unrelated GitHub outage. **Do not read that as the gate working.** If you want the publish gated, the change is Pages `build_type: workflow` with the check ahead of the deploy step; that is a real change to the publish path and must not be attempted while Pages is degraded.

**Why the old wording was dangerous:** it is the fact an agent reaches for while diagnosing a possibly-missing publish. "Nothing deploys" turns a stale public page into a non-event, and this lane's only user-visible surface — the 222-row page whose per-row report links are G-4's detection path (G-3's until it closed 2026-08-26) — is published by exactly this mechanism.

## Commands

- `npm test` — network-free self-tests, all wired into CI (`reverify.test.mjs` fails if you add another without a workflow step, and prints the live count so this line cannot go stale)
- `npm run check` — LIVE checks: mirror diff + cross-surface claim re-verification
- `npm run verify` — **the day's FIRST command.** Runs `npm test && npm run check` through the fleet receipt writer, exits with the gate's TRUE code, and records `{exitCode, sha, at}` to `tmp/.verify-receipt.json`. Use this rather than bare `npm run check`: `agent-status` REFUSES the day's first bus post unless a receipt exists at the **current** HEAD, so the bare check leaves you refused later, at a worse moment. A receipt for a different commit says nothing about the code you have. Never reach for `--no-verify-receipt` / `CC_VERIFY_RECEIPT_DISABLED=1` — the override buys one post and loses the cadence. Wired 2026-08-19 (`cb4f6f5`); added here 2026-08-20 after it had been the documented first action for a day while absent from this list.
  **Run it in this exact shape — the obvious form is refused:**
  ```bash
  npm run verify > tmp/verify-out.txt 2>&1; echo "EXIT=$?"
  ```
  Piping it into `tail` or `head` to skim the output is refused by the pre-commit corruption guard, because the pipe's exit code is the pager's and a real failure would read as green — the exact defect that made this lane's alarm fake for its first two days. The refusal is correct and nobody should narrow it; this line exists so the round-trip it costs happens zero times per session instead of once. Same shape for any gate in this list. Added 2026-08-23 after tripping it twice in one morning.
- `npm run close:primer` — **close-boundary gate**, not a cadence check: fails if `docs/cold-starts/<tomorrow-MT>.md` is missing. Deliberately NOT in `npm test`, `npm run check` or CI — tomorrow's primer legitimately does not exist for most of the day, so a cadence placement would be red from midnight until close-session ran, and a permanently-red alarm is this lane's founding defect. Its self-test IS in the offline battery. Added 2026-08-20 after that day opened with no primer and the miss left no trace anywhere.
- `npm run deferrals` — the deferral gate WITH its pull-request leg (A-25, 2026-08-25). The items leg already runs inside `npm run check`; this adds open PRs, needs `gh`, and **exits 2 rather than 0 when it cannot run**, which is why that leg is off the CI rail. It fires on EXPIRY and on MALFORMEDNESS (a declared deferral missing `expiresOn` or `releaseTest`) and is SILENT on a well-formed unexpired one however many exist — firing on existence would be the permanently-red alarm this repo was founded on, so do not "improve" it into doing that. **Its `N declared deferral(s)` line measures ADOPTION, not inventory:** a deferral still written as prose in a note field is invisible to it, which is exactly the population it was built because we could not track. Read a rise as better coverage, not more debt.
- `npm run traffic` — sample GitHub traffic into `continuity/traffic.json` (W-6; the API keeps only 14 days, so skipping this for a fortnight loses those days permanently). Needs `gh` auth; never runs in CI.
- `npm run reports` — **G-4's PRIMARY indicator, and G-3's leading one until G-3 closed 2026-08-26** (shipped 2026-08-25). It counts outside report ARRIVALS via the per-row "looks wrong?" link on all 222 rows of the public page. **It matters more now than it did:** G-4 requires an outside action whose causal path contains no artifact we authored and sent, and an issue arriving through a per-row link is exactly that shape — so this stopped being a leading indicator and became the thing itself. Needs `gh`; never runs in CI; renders a figure and no verdict. **It counts arrivals, never clicks** — the page is static on GitHub Pages and this lane is not adding an analytics stack; a click measures curiosity, a filed report measures someone who read a row, disbelieved it and acted. **It refuses to print a bare zero**: it reports the RAW issue count, excludes ours by AUTHOR (the drift alarm posts as `app/github-actions`), and requires the classified parts to SUM to the raw total — exiting 2 on an empty fetch and 3 on a reconcile failure, because a zero from a dead probe is indistinguishable from a measured one. Uses `gh issue list`, NOT the REST `.../issues` endpoint, which counts pull requests as issues.
- `npm run catches` — Tier-1 indicator: verified catches on named records, per week (derived from git history, so it cannot go stale). Renders a figure and no verdict; never fails a build, never runs in CI. A month of zeros is the signal to adopt a SECOND surface — but **the zeros do not fire that alone** (amended 2026-08-14): read the findings over the same window first, and dry means no movements AND no findings. **Read the daily reports' classification sentences for that leg, NOT `docs/findings/` alone** (corrected 2026-08-23): the standing puts one classification sentence in every report, and only findings big enough to earn a writeup also get a file. On 2026-08-23 the directory held nothing newer than 08-19 while the 08-21 and 08-22 reports classified eight findings between them, so this leg read literally would have called a busy fortnight dry — and pointed at a second surface on the strength of it. The 08-21 report asserted "findings are not dry" and was correct, but an author reading their own week is not the instrument this rule names. This counts drift DETECTION only; G-1's single acknowledgement came from manual error detection the indicator is built not to see. Adopting a second surface stays a surfaced decision for David, never self-approved on a firing rule.
- `npm run resnap` — the WHOLE post-snapshot ratchet in order: `--snapshot`, then `extract-pins.mjs`, then `render-state-block.mjs`. Prefer this over running the three by hand; on 2026-08-14 a cycle that did the first two looked finished and `npm run check` still exited 1 on the state block. Content-idempotent when already in sync (only the manifest's `fetchedAt` moves — don't commit that alone). **A pin-moving cycle needs a SECOND `render-site.mjs` after the commit, and the reason is not what the 2026-08-24 commit body says.** That body claims `index.html` embeds the README drift count — it does not; `render-site.mjs` opens exactly `ledger/claims.json` and `ledger/…/manifest.json` and never reads README.md. What actually happens: each row's date comes from `lastChanged()` in `scripts/lookup.mjs`, which shells `git log -S` over **committed** history. `resnap` renders while the new `claims.json` is still uncommitted, so a moved pin has no committed history yet and the page publishes `date unknown` for exactly the rows that just moved — the ones a reader most wants dated. It is not a prose or hand-edit problem and it recurs on every pin-moving cycle. `render-site --check` inside `npm run check` catches it once the commit exists, which is why the definition of done below requires that check AFTER committing, not before. **And it bites the ORDER control, not only the text.** In the same pre-commit render the two rows displayed `date unknown` while their `data-changed` attribute still read the old `2026-07-24` — so the label and the sort key disagreed, and the sort key is exactly what the most-recently-updated ordering reads. A reader could therefore be ordered by a date the page was simultaneously declining to show them.

- `node scripts/extract-pins.mjs` — regenerate generated pins (run after EVERY `--snapshot`)

## Hard invariants

- **Never commit secrets** — this repo is PUBLIC. Credentials come from user-scope env at run time, never from repo files or CI secrets.
- **In a fresh clone, arm the pre-commit scan first: `git config core.hooksPath .githooks`.** `hooksPath` is per-clone config, so the committed hook is the recipe and not the guarantee. It runs `history-sweep.mjs --staged` and refuses a commit whose staged diff carries secret-shaped content.
- **`main` is protected by a repository ruleset** (`main-history-integrity`, no bypass actors): deletion and non-fast-forward pushes are blocked for everyone including the owner. A rejected force-push is the control working, not a broken remote. A deliberate history rewrite requires disabling the ruleset first — that friction is the point.
- **Don't hand-edit** `ledger/teorth-optimizationproblems/**` (machine mirror; refresh only via `--snapshot`) or the `generated: true` pins in `ledger/claims.json` (rewritten wholesale by `extract-pins.mjs`). Only hand claims C-1…C-11 are hand-edited.
- **A red drift run is the alarm, not a bug.** Verify against primary sources first, then `--snapshot` + `extract-pins.mjs` + commit deliberately. Never snapshot to silence the alarm. Editorial drift is real drift.
- **`UNREACHABLE` is not `BROKEN`.** `BROKEN` = the source was read and the pinned string is gone (a record moved). `UNREACHABLE` = it was never read. The alarm must never title the second as drift. The run still goes RED either way — unreachable means unverified, and a green there launders an unverifiable into a pass. Never make a 429 non-fatal.
- **When an item CLOSES, the close commit body lists the files that still mention its id — and the grep covers `scripts/` and string literals in output, not `docs/` alone** (approved 2026-08-27). Seven instances now of a closed gate surviving in text that cited it. Instance six was `report-rate.mjs`, whose output line still read "G-3 asks for n=1" the day after G-3 closed, and it slipped through a sweep that had ALREADY been done and recorded: `6b4bc09` says "the citing-text sweep done", and that sweep was doc-scoped. **A doc-scoped sweep makes instance seven look exactly like instance six.** Run `grep -rn "<id>" scripts/ docs/ *.md` at close and paste the hits into the commit. Deliberately NOT a linter: a checker that audits checkers owes the W-7 question itself, and every instance so far was a judgment no assertion could have made. The sweep goes where the decision is.
- **Close the drift issue when the drift is resolved, naming the resolving sha.** A permanently-open `Drift:` issue teaches the next reader to ignore the alarm. **Close it by hand with a comment naming the sha; do NOT use a `Closes #N` trailer in a drift-resolution commit.** The trailer works — GitHub's close event carries `commit_id`, so the audit trail exists — but it fires the moment the commit lands, before anyone has written down what was verified against which primary source, and the issue thread itself then reads as ended with no account of how. The hand comment is the account. To audit any past drift issue, read the close event's `commit_id` (`gh api repos/OWNER/REPO/issues/N/timeline`) and then read that commit body for the verification paragraph.
- **A feature branch gets NO CI run from pushing** (`push: branches: [main]`). Use `gh workflow run reverify.yml --ref <branch>`. Do not dispatch it repeatedly — ~450 requests per run, and it shares a rate-limit budget with the scheduled run the streak is measured on.
- **Before validating a held branch on a runner, check it still merges** (`git merge-tree --write-tree main <branch>`). A verdict on an unmergeable sha is a verdict about code that will never land.
- **A `manual: true` claim reports UNVERIFIED, never green.** A local pass does not license automating it — the upstream 403 is IP-dependent, so only a green CI run is evidence about CI.
- **Never read an exit code through a pipe**, in CI (`shell: bash` required — the runner default has no `pipefail`) or locally: the pipe's exit 0 wins and a real failure passes green.
- **Ship no detector without demonstrating both answers** — fires when the condition is present, silent when absent. Prove the test mutation landed (`git diff --numstat`) first; files are CRLF, so a `\n` pattern silently no-ops.
- **Outward gate:** no upstream contact (PR, correction, email) and no public flip without an adversarial refute-it review AND David's explicit approval.
- **Scope discipline for delegated work:** change only the files named in the task; if blocked, STOP and report rather than working around a check.
- **Commits carry the exact model identity:** `Co-Authored-By: <exact model name> <noreply@anthropic.com>` — never a generic "AI".
- Definition of done: `npm test` passes, `npm run check` is green (or the drift is deliberately resolved and committed), docs/continuity updated, pushed.
