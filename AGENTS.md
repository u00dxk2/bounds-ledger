## What this is

A reproducible, continuously re-verified ledger of drifting mathematical records (bounds / constants / certificates) that alarms when a cited record moves. Node stdlib + `fetch` only; `npm install` is a no-op. The repo is PUBLIC (since 2026-08-08).

**EVERY push to `main` PUBLISHES, doc-only commits included — there are TWO automations, not one: the Actions drift job and the GitHub Pages build.** Pages (`build_type: legacy`, source `main` at `/`) builds on every commit and serves `index.html` at `https://u00dxk2.github.io/bounds-ledger/`. Measured, not read off a config field: the builds API is the only observable — ask whether a build ROW exists for the commit (`gh api repos/u00dxk2/bounds-ledger/pages/builds`; 30 consecutive rows, one per commit, doc-only included). **THE PUBLISH IS NOT CI-GATED — Pages legacy builds fire on push and wait for NOTHING** (measured 2026-08-26: the build row for a settled commit was created two seconds BEFORE its CI run started), so `render-site --check` in CI runs in parallel with the publish, not before it — on an ordinary day a bad page goes live and CI tells you afterwards; the pre-commit hook closes that window at COMMIT time, and truly gating the publish means Pages `build_type: workflow`, a real change to the publish path (A-31's open question). This matters because the 222-row public page — the lane's only user-visible surface and G-4's detection path — is published by exactly this mechanism. The measurement narrative (the timestamp pair, the `784e4f4` near-miss, the five-day stale "Nothing deploys" line and why it was dangerous): `docs/agents-md-archive.md` § 2026-08-31.

## Commands

- `npm test` — network-free self-tests, all wired into CI (`reverify.test.mjs` fails if you add another without a workflow step, and prints the live count so this line cannot go stale)
- `npm run check` — LIVE checks: mirror diff + cross-surface claim re-verification
- `npm run verify` — **the day's FIRST command.** Runs `npm test && npm run check` through the fleet receipt writer, exits with the gate's TRUE code, and records `{exitCode, sha, at}` to `tmp/.verify-receipt.json`. Use this rather than bare `npm run check`: `agent-status` REFUSES the day's first bus post unless a receipt exists at the **current** HEAD, so the bare check leaves you refused later, at a worse moment. A receipt for a different commit says nothing about the code you have. Never reach for `--no-verify-receipt` / `CC_VERIFY_RECEIPT_DISABLED=1` — the override buys one post and loses the cadence.
  **WHEN IS IT OWED? Once, after the last commit that touches CODE — doc-only commits after it do NOT invalidate it** (fleet answer, relayed by the orchestrator 2026-08-28). The fleet reader already carries the carve-out: a receipt whose sha is an **ancestor** of HEAD with only doc-shaped paths changed since (`docs/`, `*.md`, `continuity/`, `tmp/`) PASSES with a stderr note naming the range; **one code path in that range still refuses, and the refusal names it.** This matters because the gate is ~450 network requests: three commits in a day do not mean three runs. (Observed example + adoption dates: `docs/agents-md-archive.md`.)
  **Run it in this exact shape — the obvious form is refused:**
  ```bash
  npm run verify > tmp/verify-out.txt 2>&1
  ```
  Piping it into `tail` or `head` to skim the output is refused by the pre-commit corruption guard — the pipe's exit code is the pager's, the defect that made this lane's alarm fake for its first two days. The refusal is correct and nobody should narrow it; same shape for any gate in this list. (Original note: `docs/agents-md-archive.md`.)
  **The exit code comes from the receipt, never a trailing `echo`** (2026-08-31). The old `; echo "EXIT=$?"` was redundant — `tmp/.verify-receipt.json` records `exitCode` beside the sha it was green AT — and it was a `;` compound, the shape the permission classifier parks on. `docs/daily-config.md` already wrote it without the echo; this reconciles the two.
- `npm run close:primer` — **close-boundary gate**, not a cadence check: fails if `docs/cold-starts/<tomorrow-MT>.md` is missing. Deliberately NOT in `npm test`, `npm run check` or CI — tomorrow's primer legitimately does not exist for most of the day, and a permanently-red alarm is this lane's founding defect. Its self-test IS in the offline battery. (Origin: `docs/agents-md-archive.md`.)
- `npm run deferrals` — the deferral gate WITH its pull-request leg (A-25, 2026-08-25). The items leg already runs inside `npm run check`; this adds open PRs, needs `gh`, and **exits 2 rather than 0 when it cannot run**, which is why that leg is off the CI rail. It fires on EXPIRY and on MALFORMEDNESS (a declared deferral missing `expiresOn` or `releaseTest`) and is SILENT on a well-formed unexpired one however many exist — firing on existence would be the permanently-red alarm this repo was founded on, so do not "improve" it into doing that. **Its `N declared deferral(s)` line measures ADOPTION, not inventory:** a deferral still written as prose in a note field is invisible to it, which is exactly the population it was built because we could not track. Read a rise as better coverage, not more debt.
- **Rendering the public page at any viewport needs NO Chrome extension** — `playwright-cli` is installed machine-wide: `playwright-cli open https://u00dxk2.github.io/bounds-ledger/`, then `resize 390 844`, then `eval` / `snapshot`. The extension being unavailable is a fact about ONE route, not about the capability; the fleet preference for this tool lives in **skylark-site's** `AGENTS.md`, so grepping this repo for it returns nothing. (The A-36 two-day stall this line comes from: `docs/agents-md-archive.md`.)
- `npm run traffic` — sample GitHub traffic into `continuity/traffic.json` (W-6; the API keeps only 14 days, so skipping this for a fortnight loses those days permanently). Needs `gh` auth; never runs in CI.
- `npm run reports` — **G-4's PRIMARY indicator** (shipped 2026-08-25): counts outside report ARRIVALS via the per-row "looks wrong?" link on the public page — an issue arriving that way is exactly G-4's shape (no artifact we authored and sent in the causal path). Needs `gh`; never runs in CI; renders a figure and no verdict; **counts arrivals, never clicks**. **It refuses to print a bare zero**: it reports the RAW issue count, excludes ours by AUTHOR (the drift alarm posts as `app/github-actions`), and requires the classified parts to SUM to the raw total — exit 2 on an empty fetch, 3 on a reconcile failure, because a zero from a dead probe is indistinguishable from a measured one. Uses `gh issue list`, NOT the REST `.../issues` endpoint, which counts pull requests as issues. (Original, with the G-3 history: `docs/agents-md-archive.md`.)
- `npm run catches` — Tier-1 indicator: verified catches on named records, per week (derived from git history, so it cannot go stale). Renders a figure and no verdict; never fails a build, never runs in CI. A month of zeros is the signal to adopt a SECOND surface — but **the zeros do not fire that alone** (amended 2026-08-14): dry means no movements AND no findings, and **read the daily reports' classification sentences for the findings leg, NOT `docs/findings/` alone** (corrected 2026-08-23) — only findings big enough to earn a writeup also get a file, so the directory read literally can call a busy fortnight dry. This counts drift DETECTION only. Adopting a second surface stays a surfaced decision for David, never self-approved on a firing rule. (The 2026-08-23 mis-read behind the corrected leg: `docs/agents-md-archive.md`.)
- `npm run resnap` — the WHOLE post-snapshot ratchet in order: `--snapshot`, then `extract-pins.mjs`, then `render-state-block.mjs`. Prefer this over running the three by hand; on 2026-08-14 a cycle that did the first two looked finished and `npm run check` still exited 1 on the state block. Content-idempotent when already in sync (only the manifest's `fetchedAt` moves — don't commit that alone). **A pin-moving cycle needs a SECOND `render-site.mjs` AFTER the commit:** each row's date comes from `lastChanged()` in `scripts/lookup.mjs`, which shells `git log -S` over **committed** history, so a render while the new `claims.json` is still uncommitted publishes `date unknown` — and a stale `data-changed` sort key, the very key the most-recently-updated ordering reads — for exactly the rows that just moved. It recurs on every pin-moving cycle; `render-site --check` inside `npm run check` catches it once the commit exists, which is why the definition of done below requires that check AFTER committing, not before. (Why the 2026-08-24 commit body's own explanation of this is wrong: `docs/agents-md-archive.md`.)
- `node scripts/reverify.mjs --check | --snapshot` — diff mirror vs upstream / refresh it
- `node scripts/extract-pins.mjs` — regenerate generated pins (run after EVERY `--snapshot`)
- `node scripts/check-claims.mjs` · `check-brief.mjs` (needs `CC_PROMPTS_PIN`) · `history-sweep.mjs`

## Hard invariants

- **Never commit secrets** — this repo is PUBLIC. Credentials come from user-scope env at run time, never from repo files or CI secrets.
- **In a fresh clone, arm the pre-commit scan first: `git config core.hooksPath .githooks`.** `hooksPath` is per-clone config, so the committed hook is the recipe and not the guarantee. It runs `history-sweep.mjs --staged` and refuses a commit whose staged diff carries secret-shaped content.
- **`main` is protected by a repository ruleset** (`main-history-integrity`, no bypass actors): deletion and non-fast-forward pushes are blocked for everyone including the owner. A rejected force-push is the control working, not a broken remote. A deliberate history rewrite requires disabling the ruleset first — that friction is the point.
- **Don't hand-edit** `ledger/teorth-optimizationproblems/**` (machine mirror; refresh only via `--snapshot`) or the `generated: true` pins in `ledger/claims.json` (rewritten wholesale by `extract-pins.mjs`). Only hand claims C-1…C-11 are hand-edited.
- **A red drift run is the alarm, not a bug.** Verify against primary sources first, then `--snapshot` + `extract-pins.mjs` + commit deliberately. Never snapshot to silence the alarm. Editorial drift is real drift.
- **`UNREACHABLE` is not `BROKEN`.** `BROKEN` = the source was read and the pinned string is gone (a record moved). `UNREACHABLE` = it was never read. The alarm must never title the second as drift. The run still goes RED either way — unreachable means unverified, and a green there launders an unverifiable into a pass. Never make a 429 non-fatal.
- **When an item CLOSES, the close commit body lists the files that still mention its id — and the grep covers `scripts/` and string literals in output, not `docs/` alone** (approved 2026-08-27; seven instances now of a closed gate surviving in text that cited it, and instance six slipped through a sweep that had ALREADY been done and recorded because that sweep was doc-scoped). Run `grep -rn "<id>" scripts/ docs/ *.md` at close and paste the hits into the commit. Deliberately NOT a linter: every instance so far was a judgment no assertion could have made. The sweep goes where the decision is.
  **AND WHEN THE CLOSE RECORDS A PROHIBITION, SWEEP THE ARTIFACT PATH TOO, NOT ONLY THE ID** (approved 2026-08-28): the id sweep greps the ID, not the THING — so when a resolution forbids something, also `grep -rn "<the artifact path>" continuity/items.json` and reconcile every open row it hits. Same deliberate refusal to mechanize. (The instances behind both rules: `docs/agents-md-archive.md`.)
- **Close the drift issue when the drift is resolved, naming the resolving sha.** A permanently-open `Drift:` issue teaches the next reader to ignore the alarm. **Close it by hand with a comment naming the sha; do NOT use a `Closes #N` trailer in a drift-resolution commit.** The trailer works — GitHub's close event carries `commit_id`, so the audit trail exists — but it fires the moment the commit lands, before anyone has written down what was verified against which primary source, and the issue thread itself then reads as ended with no account of how. The hand comment is the account. To audit any past drift issue, read the close event's `commit_id` (`gh api repos/OWNER/REPO/issues/N/timeline`) and then read that commit body for the verification paragraph.
- **A feature branch gets NO CI run from pushing** (`push: branches: [main]`). Use `gh workflow run reverify.yml --ref <branch>`. Do not dispatch it repeatedly — ~450 requests per run, and it shares a rate-limit budget with the scheduled run the streak is measured on.
- **Before validating a held branch on a runner, check it still merges** (`git merge-tree --write-tree main <branch>`). A verdict on an unmergeable sha is a verdict about code that will never land.
- **A `manual: true` claim reports UNVERIFIED, never green.** A local pass does not license automating it — the upstream 403 is IP-dependent, so only a green CI run is evidence about CI.
- **Never read an exit code through a pipe**, in CI (`shell: bash` required — the runner default has no `pipefail`) or locally: the pipe's exit 0 wins and a real failure passes green.
- **Ship no detector without demonstrating both answers** — fires when the condition is present, silent when absent. Prove the test mutation landed (`git diff --numstat`) first; files are CRLF, so a `\n` pattern silently no-ops.
- **Outward gate:** no upstream contact (PR, correction, email) and no public flip without an adversarial refute-it review AND David's explicit approval.
- **Scope discipline for delegated work:** change only the files named in the task; if blocked, STOP and report rather than working around a check.
- **Commits carry the exact model identity:** `Co-Authored-By: <exact model name> <noreply@anthropic.com>` — never a generic "AI".
- Definition of done: `npm test` passes, `npm run check` is green (or the drift is deliberately resolved and committed), docs/continuity updated, pushed.
