## What this is

A reproducible, continuously re-verified ledger of drifting mathematical records (bounds / constants / certificates) that alarms when a cited record moves. Node stdlib + `fetch` only; there are no dependencies to install (`npm install` only runs `prepare`, which arms the hook path). The repo is PUBLIC (since 2026-08-08). Every doc, with a start-here order: `docs/README.md`.

**EVERY push to `main` PUBLISHES, doc-only commits included — there are TWO automations, not one: the Actions drift job and the GitHub Pages build.** Pages (`build_type: legacy`, source `main` at `/`) builds once per PUSH, not per commit, and serves `index.html` at `https://u00dxk2.github.io/bounds-ledger/`. **A multi-commit push publishes only its TIP — intermediates never go live.** Measured, not read off a config field: the builds API is the only observable — ask whether a build ROW exists for the push tip (`gh api repos/u00dxk2/bounds-ledger/pages/builds`; measured 2026-09-01: a two-commit push made ONE row; `7ba4f3c`/`a3dc9a5`/`348593f` present, `3145ed9` absent; doc-only too). **THE PUBLISH IS NOT CI-GATED — Pages legacy builds fire on push and wait for NOTHING** (measured 2026-08-26: a settled commit's build row predated its CI run by two seconds), so nothing in CI stands between a push and the publish — and CI runs `render-site --check` only since 2026-10-05, in its own workflow `page-check.yml` at fetch-depth 0 on every push to main (A-31 reopened by the orchestrator; before that CI ran only the `--selftest`s, corrected 2026-10-01 by adversarial review), and it still never runs `render-constant-pages --check`; even so, a stale or bad `index.html` goes live first and `page-check` reports it minutes later, and a stale `c/` page goes live and only a local `npm run check` says so (CI does run `render-ramsey --check` on ramsey.html); the pre-commit hook closes that window at COMMIT time, but only for `index.html` and only when it is staged — it never compares the `c/` pages, and truly gating it means Pages `build_type: workflow` (A-31). Since 2026-10-05 the hook also refuses a staged page that differs from the working copy and a staged delete or rename of `index.html`; the routes it still cannot see (partial staging of renderer inputs, a non-regular file mode, automatic merge commits, `--no-verify`) are named in its header, and `A-72` records that A-31's 2026-09-10 decline assumed a CI `render-site --check` that did not exist then; `page-check.yml` now provides it for `index.html`, after publish. This matters: the public page — our only user-visible surface and G-4's detection path — ships by this mechanism. **Row count is ONE PER CONSTANT — read it, never recall it: `grep -c '<tr id=' index.html`. ## Commands

- `npm test` — network-free self-tests, all wired into CI (`reverify.test.mjs` fails if you add another without a workflow step, and prints the live count so this line cannot go stale)
- `npm run check` — LIVE checks: twelve `check:*` legs, listed in `package.json` under `check` (mirror diff, cross-surface claim re-verification, the Ramsey survey re-derivation, the README state block, the index, constant-page and Ramsey-page renders, audit lines, notation coverage, the deferral gate, the advisory brief leg and the entry guard). Read the list there; never count it from here.
- `npm run verify` — **the day's FIRST command.** Runs `npm test` plus every `check:*` leg EXCEPT `check:entry-guard` and `check:notation` (`package.json` `verify:steps`), so a green receipt is not a green `npm run check`, through the fleet receipt writer, exits with the gate's TRUE code, and records `{exitCode, sha, at}` to `tmp/.verify-receipt.json`. Use this rather than bare `npm run check`: `agent-status` REFUSES the day's first bus post unless a receipt exists at the **current** HEAD, so the bare check leaves you refused later, at a worse moment. A receipt for a different commit says nothing about the code you have. Never reach for `--no-verify-receipt` / `CC_VERIFY_RECEIPT_DISABLED=1` — the override buys one post and loses the cadence.
  **WHEN IS IT OWED? Once, after the last commit that touches CODE — doc-only commits after it do NOT invalidate it** (fleet answer, relayed by the orchestrator 2026-08-28). The fleet reader already carries the carve-out: a receipt whose sha is an **ancestor** of HEAD with only doc-shaped paths changed since (`docs/`, `*.md`, `continuity/`, `tmp/`) PASSES with a stderr note naming the range; **one code path in that range still refuses, and the refusal names it.** This matters because the gate is ~450 network requests: three commits in a day do not mean three runs. (Observed example + adoption dates: `docs/agents-md-archive.md`.)
  **Run it in this exact shape — the obvious form is refused:**
  ```bash
  npm run verify > tmp/verify-out.txt 2>&1
  ```
  Piping it into `tail` or `head` to skim the output is refused by the pre-commit corruption guard — the pipe's exit code is the pager's, the defect that made this lane's alarm fake for its first two days. The refusal is correct and nobody should narrow it; same shape for any gate in this list. (Original note: `docs/agents-md-archive.md`.)
  **The exit code comes from the receipt, never a trailing `echo`** (2026-08-31). The old `; echo "EXIT=$?"` was redundant — `tmp/.verify-receipt.json` records `exitCode` beside the sha it was green AT — and it was a `;` compound, the shape the permission classifier parks on. `docs/daily-config.md` already wrote it without the echo; this reconciles the two.
- `npm run close:primer` — **close-boundary gate**, not a cadence check: fails if `docs/cold-starts/<tomorrow-MT>.md` is missing. Deliberately NOT in `npm test`, `npm run check` or CI — tomorrow's primer legitimately does not exist for most of the day, and a permanently-red alarm is this lane's founding defect. Its self-test IS in the offline battery. (Origin: `docs/agents-md-archive.md`.)
- `npm run deferrals` — the deferral gate WITH its pull-request leg (A-25, 2026-08-25). The items leg already runs inside `npm run check`; this adds open PRs, needs `gh`, and **exits 2 rather than 0 when it cannot run**, which is why that leg is off the CI rail. It fires on EXPIRY and on MALFORMEDNESS (a declared deferral missing `expiresOn` or `releaseTest`) and is SILENT on a well-formed unexpired one however many exist — firing on existence would be the permanently-red alarm this repo was founded on, so do not "improve" it into doing that. **Its `N declared deferral(s)` line measures ADOPTION, not inventory:** a deferral still written as prose in a note field is invisible to it, which is exactly the population it was built because we could not track. Read a rise as better coverage, not more debt.

- `npm run resnap` — the WHOLE post-snapshot ratchet in order, six steps (`package.json` `resnap`): `--snapshot`, `extract-pins.mjs`, `render-state-block.mjs`, `render-site.mjs`, `open-pulls.mjs --fetch`, `render-constant-pages.mjs`. Prefer this over running them by hand; on 2026-08-14 a cycle that did the first two looked finished and `npm run check` still exited 1 on the state block. Content-idempotent when already in sync (only the manifest's `fetchedAt` moves — don't commit that alone). **A pin-moving cycle needs a SECOND `render-site.mjs` AFTER the commit:** each row's date comes from `lastChanged()` in `scripts/lookup.mjs`, which shells `git log -S` over **committed** history, so a render while the new `claims.json` is still uncommitted publishes `date unknown` — and a stale `data-changed` sort key, the very key the most-recently-updated ordering reads — for exactly the rows that just moved. ## Hard invariants

- **Never commit secrets** — this repo is PUBLIC. Credentials come from user-scope env at run time, never from repo files or CI secrets.
- **THE DRIFT ALARM'S STDOUT IS A PUBLIC SURFACE. Anything `reverify.mjs --check`, `check-claims.mjs` or `extract-ds1.mjs --check` prints is published VERBATIM into a public GitHub issue when the alarm fires** — `.github/workflows/reverify.yml` tees all three into `finding.txt` (the three `tee -a finding.txt` steps; grep for them, since line numbers move) and the failure handler files it. So a line added to any of those three for OUR eyes is not for our eyes. Measured 2026-09-19 by adversarial review, on a `CANDIDATE CAUSAL EVENT` label whose public form had been *permanently declined* on 2026-09-02: it would have auto-published the very thing that decision forbade. An internal-only annotation belongs behind an explicit boundary — `check()`'s `causal` parameter, `!process.env.CI` — with a test proving the annotation is absent under `CI=true` while the ordinary classification survives. This is the lane's "a decision that forbids a channel forbids the CONTENT" rule, and the trap is that the forbidden channel does not look like a channel.
- **In a fresh clone, arm the pre-commit scan first: `git config core.hooksPath .githooks`.** `hooksPath` is per-clone config, so the committed hook is the recipe and not the guarantee. It runs `history-sweep.mjs --staged` and refuses a commit whose staged diff carries secret-shaped content.
- **`main` is protected by a repository ruleset** (`main-history-integrity`, no bypass actors): deletion and non-fast-forward pushes are blocked for everyone including the owner. A rejected force-push is the control working, not a broken remote. A deliberate history rewrite requires disabling the ruleset first — that friction is the point.
- **Don't hand-edit** `ledger/teorth-optimizationproblems/**` (machine mirror; refresh only via `--snapshot`) or the `generated: true` pins in `ledger/claims.json` (rewritten wholesale by `extract-pins.mjs`). Only hand claims C-1…C-14 are hand-edited (C-12…C-14 are the revision pins on Small Ramsey Numbers, the second watched area, `A-54`).
- **A red drift run is the alarm, not a bug.** Verify against primary sources first, then `--snapshot` + `extract-pins.mjs` + commit deliberately. Never snapshot to silence the alarm. Editorial drift is real drift.
- **`UNREACHABLE` is not `BROKEN`.** `BROKEN` = the source was read and the pinned string is gone (a record moved). `UNREACHABLE` = it was never read. The alarm must never title the second as drift. The run still goes RED either way — unreachable means unverified, and a green there launders an unverifiable into a pass. Never make a 429 non-fatal.
- **When an item CLOSES, the close commit body lists the files that still mention its id — and the grep covers `scripts/` and string literals in output, not `docs/` alone** (approved 2026-08-27; seven instances now of a closed gate surviving in text that cited it, and instance six slipped through a sweep that had ALREADY been done and recorded because that sweep was doc-scoped). Run `grep -rn "<id>" scripts/ docs/ *.md` at close and paste the hits into the commit. Deliberately NOT a linter: every instance so far was a judgment no assertion could have made. The sweep goes where the decision is.
  **AND WHEN THE CLOSE RECORDS A PROHIBITION, SWEEP THE ARTIFACT PATH TOO, NOT ONLY THE ID** (approved 2026-08-28): the id sweep greps the ID, not the THING — so when a resolution forbids something, also `grep -rn "<the artifact path>" continuity/items.json` and reconcile every open row it hits. Same deliberate refusal to mechanize. (The instances behind both rules: `docs/agents-md-archive.md`.)
- **Close the drift issue when the drift is resolved, naming the resolving sha.** A permanently-open `Drift:` issue teaches the next reader to ignore the alarm. **Close it by hand with a comment naming the sha; do NOT use a `Closes #N` trailer in a drift-resolution commit.** The trailer works — GitHub's close event carries `commit_id`, so the audit trail exists — but it fires the moment the commit lands, before anyone has written down what was verified against which primary source, and the issue thread itself then reads as ended with no account of how. The hand comment is the account. To audit any past drift issue, read the close event's `commit_id` (`gh api repos/OWNER/REPO/issues/N/timeline`) and then read that commit body for the verification paragraph.
- **A feature branch gets NO CI run from a push alone** (`push: branches: [main]`). A pull request into `main` does get `reverify.yml` and `page-check.yml` runs (`pull_request: branches: [main]`), except a STACKED pull request, whose base is not `main`. Otherwise use `gh workflow run reverify.yml --ref <branch>`. Do not dispatch it repeatedly — ~450 requests per run, and it shares a rate-limit budget with the scheduled run the streak is measured on.
- **Before validating a held branch on a runner, check it still merges** (`git merge-tree --write-tree main <branch>`). A verdict on an unmergeable sha is a verdict about code that will never land.
- **A `manual: true` claim reports UNVERIFIED, never green.** A local pass does not license automating it — the upstream 403 is IP-dependent, so only a green CI run is evidence about CI.
- **Never read an exit code through a pipe**, in CI (`shell: bash` required — the runner default has no `pipefail`) or locally: the pipe's exit 0 wins and a real failure passes green.
- **Ship no detector without demonstrating both answers** — fires when the condition is present, silent when absent. Prove the test mutation landed (`git diff --numstat`) first; files are CRLF, so a `\n` pattern silently no-ops.
- **Outward gate:** no upstream contact (PR, correction, email) and no public flip without an adversarial refute-it review AND David's explicit approval. Never contact a maintainer on your own. **Extended by David on 2026-08-01: at least one adversarial review on EVERYTHING this project produces that might touch the public**, not just sends: the flip package, README-as-product, brief blocks, any artifact a stranger could read.
- **Never kill a node process by name, by age, or because it looks orphaned** — the process table is shared by every pane on this machine. Only a PID from your own pidfile, or one whose command line names this repo (`docs/gotchas.md` has the two permitted shapes).
- **Never run `doppler` in any form** — this lane does not use it, and a secrets CLI's output belongs nowhere near a transcript.
- **Scope discipline for delegated work:** change only the files named in the task; if blocked, STOP and report rather than working around a check.
- **Commits carry the exact model identity:** `Co-Authored-By: <exact model name> <noreply@anthropic.com>` — never a generic "AI".
- Definition of done: `npm test` passes, `npm run check` is green (or the drift is deliberately resolved and committed), docs/continuity updated, pushed.
