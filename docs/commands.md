## Indicators (never a gate; none runs in CI beyond a `--selftest`)

- `npm run traffic` — sample GitHub traffic into `continuity/traffic.json` (W-6; the API keeps only 14 days, so skipping this for a fortnight loses those days permanently). Needs `gh` auth; never runs in CI.
- `npm run reports` — **G-4's PRIMARY indicator** (shipped 2026-08-25): counts outside report ARRIVALS via the per-row "looks wrong?" link on the public page — an issue arriving that way is exactly G-4's shape (no artifact we authored and sent in the causal path). Needs `gh`; never runs in CI; renders a figure and no verdict; **counts arrivals, never clicks**. **It refuses to print a bare zero**: it reports the RAW issue count, excludes ours by AUTHOR (the drift alarm posts as `app/github-actions`), and requires the classified parts to SUM to the raw total — exit 2 on an empty fetch, 3 on a reconcile failure, because a zero from a dead probe is indistinguishable from a measured one. Uses `gh issue list`, NOT the REST `.../issues` endpoint, which counts pull requests as issues. (Original, with the G-3 history: `docs/agents-md-archive.md`.)
- `npm run catches` — Tier-1 indicator: verified catches on named records, per week (derived from git history, so it cannot go stale). Renders a figure and no verdict; never fails a build, never runs in CI. A month of zeros is the signal to adopt a SECOND surface — but **the zeros do not fire that alone** (amended 2026-08-14): dry means no movements AND no findings, and **read the daily reports' classification sentences for the findings leg, NOT `docs/findings/` alone** (corrected 2026-08-23) — only findings big enough to earn a writeup also get a file, so the directory read literally can call a busy fortnight dry. This counts drift DETECTION only. Adopting a second surface stays a surfaced decision for David, never self-approved on a firing rule. (The 2026-08-23 mis-read behind the corrected leg: `docs/agents-md-archive.md`.)
- `npm run served` — `A-55`'s read: for every published file the last page-changing commit touched, does GitHub Pages serve the bytes HEAD holds? Prints SERVED / IN-FLIGHT / STALE (with the served `Last-Modified`, which names the build a reader is getting) / UNREACHABLE, and exits 1 on STALE, 2 on a refusal — an empty path set, an unreadable anchor, a commit touching no page, or a failed fetch, because a zero from a dead probe is indistinguishable from a measured one. **An INDICATOR: not in `npm run check`, and only its `--selftest` runs in CI**, since a transient GitHub failure must never turn the suite permanently red. It exists because on 2026-09-21 two Pages builds ERRORED while CI was green, `npm run verify` exited 0 and the drift alarm was silent, and the live site served the previous tip. The in-flight window is 300 s, set from a lag MEASURED at the reader (158–173 s on 2026-09-22, recorded on `A-55.lagMeasured2026_09_22`), never from a round number; `CC_SERVED_WINDOW_MS` is a documented test hook for red-arming the live path, not a setting.

- `node scripts/depth-audit.mjs` — `A-47`'s read, the depth audit David ruled on: verdict counts, the sampling rule and the denominator. Refuses a bare zero (exit 2) and a sum that does not reach the row count (exit 3). **`--corpus` computes the denominator of record** — 770 bound / 673 cited as of 2026-09-11 — printing its definition (`extract-pins.mjs`'s own bound-row rule) and four narrow checks, and refuses (exit 2) when the mirror manifest or the committed pin baseline cannot be read. An indicator, never a gate; only `--selftest` runs in CI.
- `node scripts/decimal-vs-exact.mjs [--root <dir>] [--selftest]` — `A-76`'s census: bound rows whose printed decimal sits past the exact value it stands for in the overstating direction (an upper bound printed below it, a lower bound above), the 87a shape (`$1058.565$` against 4√70035 = 1058.565066…). Three populations reported separately and never summed: IN-CELL (a value cell holding a decimal that is not a plain decimal), COMMENT (a longer decimal in the Comments cell agreeing to the cell's last place), SOURCE (`ledger/source-exact-values.json`, values a depth-audit reading recorded the source as stating, each with a quotation that must still be in its entry, never parsed from prose). **Every verdict is computed in exact rationals, never floating point** (the orchestrator's option A, 2026-10-21, after three Codex rounds kept finding precision defects): an irrational form beside a decimal marked approximate is EXACT SHOWN, not judged, and beside a bare = it is UNKNOWN. - `node scripts/arxiv-watch.mjs --fetch | --check [--control] [--out <dir>] | --selftest` — `A-81`'s newer-result watcher for the Ramsey area: asks arXiv for the `cat:math.CO AND abs:Ramsey` papers submitted from the mirrored survey revision's date through the current UTC day, and writes them to `tmp/arxiv-watch/<MT date>/papers.json` only if the distinct ids returned reconcile with the total arXiv states (it refuses more than 1,000), and `--check` judges a READING of them (`verdicts.json`, one per paper, written by reading agents to `docs/arxiv-watch-reader-brief.md`). Readers are asked to record only what a paper STATES; whether a stated bound is stronger than the value the page shows is computed by the script from `ledger/ejc-ds1/section-2-1.json` as it is on disk, against the smaller of Table Ia's and Table Ib's upper bound (the page prints both). `--check` REFUSES (exit 3) a `papers.json` whose recorded query, revision, window start or window end does not match this watcher's (the end must be the UTC date of its own `fetchedAt`), a run where any fetched paper lacks exactly one verdict, and a run with any reading marked `incomplete`. It prints no paper id, pair, quote or claimed value: its lines are fixed text, counts it computed, the ledger's own revision and date, and the validated window end from `papers.json`. The selftest checks every emitted line against an exact shape and a known fixture's lines value for value. Exit 1 means a candidate to verify by reading the paper; `--control` checks a hand-made set and makes no coverage claim. **Run it locally and never commit its output — a rule for the operator, not something the script enforces (`--out` takes any directory):** a candidate is an unverified claim about someone else's paper, and both CI output and this repo are public. The CI step runs only `--selftest`, network-free. **`--area constants` (2026-10-16) runs the same watch over the mirrored (117 at the 2026-10-18 resnap; read the count, never recall it) `teorth/optimizationproblems` constants** (default output `tmp/arxiv-watch/<MT date>/constants/`, reader brief `docs/arxiv-watch-constants-reader-brief.md`): the window starts at the mirror's `fetchedAt` date (or earlier, at `--from YYYY-MM-DD`, since 2026-10-31; never later, and `--check` must be given the same `--from` or it refuses), the query is the four automated-discovery system names (AlphaEvolve, ThetaEvolve, TTT-Discover, OpenEvolve) and nothing else yet, and `--fetch` also writes `constants.json` (ids and titles only) for the readers. Each claim is compared with the BEST row on its side, never the last-listed one, in exact decimal arithmetic (never floating point). A side holding an unverified (`*`) row, or a row the parser cannot reduce to a plain decimal, an "≈ decimal" or an "= decimal", is UNJUDGED. A shown decimal is treated as a rounding (only a bare integer or an "= decimal" identity with no "…" is exact): a claim that differs from it but lies within one unit of its last printed place, on EITHER side, is "within precision", and so is a claim equal to the digits of a print after "≈" or "…", whose bound is the expression rather than the decimal. On equal values the tighter print is the one compared. Each claim must carry a `relation` matching its side, and a STRICT claim (`<`, `>`) at the shown value is also within precision. In this area `--check`'s file errors print a fixed file label, never the `--out` path. A quote must hold the claimed value as one whole number token (digits joined by `.`, `,`, `{,}`, `\,` or a thin space are ONE token), else it is refused. UNJUDGED and within-precision claims are counted "to read by hand" and exit 1, never silently passed and never called candidates. Without `--area` the Ramsey path is unchanged, including its quote check.
