# The first real drift the armed alarm caught was editorial, not a record

**Date:** 2026-07-28 (MT) · **Surface:** `teorth/optimizationproblems` · **Verdict:** legitimate upstream
correction, snapshotted deliberately · **Records moved:** 0

## What happened

`npm run check` was clean at 12:35Z (mirror at `a002311`). At 21:36Z the same command exited 1:

```
CHANGED constants/1a.md
CHANGED constants/41b.md
2 file(s) drifted.
```

Upstream had pushed `937f4e5`. This is the **first real drift since the alarm was armed on 2026-07-24** —
days 1–5 of the green streak were all genuine "no drift" reads.

## Both changes verified against primary content, not assumed

**1 — `constants/1a.md`: a broken cross-reference, fixed.**
`See also the [page here for the minimum overlap problem](…/constants/2.html)` → `…/constants/1b.html`.
Verified: **`constants/2.md` does not exist** in the repo (the numbering is `1a`, `1b`, `20a`, `21a`, …), so
the old link was dead. `constants/1b.md` is titled *"Erdős minimum overlap constant"* — the correct target.
Upstream is right.

Worth noting: the dead link pointed at **this lane's founding finding**. Reconciliation #1 is the minimum
overlap constant, and C-1 pins it.

**2 — `constants/41b.md`: malformed LaTeX, fixed.**
`Trivially, $C\_{41a} \ge \_{41b}$` → `$C\_{41a} \ge C\_{41b}$` — a missing `C`. The corrected inequality is
also mathematically right: $C_{41b}$ (ambidextrous moving sofa) must clear **both** corners of a Z-shaped
corridor, a strictly stronger constraint than $C_{41a}$'s single L-corner, so its maximal area cannot exceed
$C_{41a}$. Upstream is right.

**No numeric bound changed in either file.** `ledger/claims.json` regenerated byte-identical (216 generated
pins, 9 hand claims) — confirming independently that no bounds-table row moved, since the pins assert
last-listed rows.

## Response (the documented discipline, executed in order)

1. `--check` red → **did not** snapshot to silence it.
2. Verified both changes against the repo's own content (file existence, page titles, the definitions in
   `41a.md`/`41b.md`).
3. `--snapshot` → 109 files @ `937f4e5`.
4. **Post-snapshot ratchet**: re-ran `extract-pins.mjs` (216 pins, unchanged) and committed with the mirror.
5. `npm test` 3/3 PASS, `npm run check` exit 0: *no drift*, `225 claim(s): 223 hold, 0 broken/unreachable,
   2 unverified (manual)`.

## One instrument scare, resolved — `git status` lied, the differ did not

After the snapshot, `git status` showed **three** changed constants files (`1a`, `21a`, `41b`) while the drift
report had named only two. A differ that misses a real change would be a serious defect in this lane, so it
was checked rather than rationalised: `git diff --numstat` lists **no entry for `21a.md`** — zero lines added
or removed. The file is byte-identical in content; it surfaced in `git status` as a line-ending/stat-cache
artifact of being rewritten by the snapshot.

**The differ was correct: exactly two files drifted.** Recording this because the opposite conclusion —
"our drift check under-reports" — was the plausible-looking one, and on this lane the standing posture is to
suspect the instrument *and then actually test it*, not to stop at the suspicion. `git status` is not a
content diff; `--numstat` is.

## Carry-forward

- A red `reverify` is not automatically a record event. **Editorial drift is real drift** and still requires
  the full verify → snapshot → re-pin cycle, because the mirror's job is byte-fidelity to the adopted
  surface, not just numeric fidelity.
- The alarm's value showed up as designed: it fired within a day of an upstream push, on a change no one
  would have noticed by hand.
