## What this lane is

A **steward** of drifting mathematical records: a reproducible, continuously re-verified ledger that alarms when a cited record (bound / constant / certificate) drifts. Not a record-search engine. Full thesis in `README.md`. Pre-launch.

**Rail: PACED (David-ruled 2026-08-01, effective 2026-08-02; replaces the lite default).** Each session: the steward cadence FIRST (read the overnight run's LOG not the badge; drift cycle if red; local `npm run check` for the W-3 advisory legs), then **≥1 concrete launch increment from A-13's backlog** (first-PR prep, README-as-product, history sweep, adversarial review — the exit is the public flip, tracked as A-13 with the decision proposed to David at streak day 14 = 2026-08-06). **Weekly forced-decision pass** over `continuity/items.json` (stale items move or die). ## Conventions (the load-bearing ones)

- **Curated vs live records: track both, labeled, NEVER blend.** A live/leaderboard claim graduates to the curated column only via a checkable construction or acceptance into a curated source. (Reconciliation #1 finding 3.)
- **A `manual: true` claim reports UNVERIFIED, never green.** When a source blocks automated fetch *from CI* (erdosproblems.com 403s datacenter IPs), the checker cannot re-run it, so it stays UNVERIFIED until a human — or a local `npm run check` — re-verifies. A done-click or hand-verify does not flip it green. That is the "never silently trusted" rule made mechanical, and 2026-07-25 is the argument for keeping it: an attempt to automate C-7 away was caught by CI within minutes precisely because UNVERIFIED-vs-UNREACHABLE is tracked honestly. **A `manual: true` pin on a blocked source is still worth adding** (C-9, 2026-07-26): it reports UNVERIFIED in CI and never touches counts or the exit code, while a local run gets a real advisory read. What failed on 7/25 was making such a pin *fetchable*, not pinning the fact.
- **Verify an artifact written FOR an audience from that audience's environment, before review** (endorsed 2026-08-16). Strip author state first: `env -u <VAR>`, fresh clone, no repo-local config. The README's 1-minute check passed only with `CC_PROMPTS_PIN`; `npm run check` exited 3 for every visitor. This is the 2026-07-25 capability/environment rule. **Degenerate case, 2026-08-18: verify a documented command by RUNNING it.** The primer's `git rev-parse --short HEAD origin/main` exited 128 and skipped the cadence; a KP-78 proof licenses only the command it ran, not adjacent lines. `--short=7` also exits 128. Finding: `docs/findings/2026-08-18-the-guard-against-a-wrong-commit-read-never-ran.md`.
- **Read one instrument against its own claim, every session (W-7, decided 2026-08-24 — SHIPPED into the cadence, not deferred again).** Pick ONE script, alarm, counter or `readCommand`; run it; ask what it claims to measure and whether its output could ever have said otherwise. Name it in the day's report in one line. Rotate — never the same one twice running. **Deliberately not a script**: a detector that audits detectors is itself an instrument owing this same question, and every instance so far was a judgment no assertion could have made. Five in ten days — `traffic-snapshot.mjs` printed a threshold retired three days earlier (`137255f`); the dry-week rule read `docs/findings/` after the classification had stopped flowing there (`123dd12`); `G-3.readCommand` was blind to a detection path we had just built; a 90-day filter would have matched all 111 rows because the field existed but did not discriminate; and the drift job auto-closes its own issue naming no resolving sha, so a reader learns that it ended and not how (2026-08-24, #29 — commented by hand).
- **The visitor path is part of the steward cadence.** Run the README's credential-free check (`node scripts/reverify.mjs --check && node scripts/check-claims.mjs`, then the tamper/restore pair) as its own cadence step. Every other indicator here measures the ledger's internal correctness — drift caught, claims holding, streak days — and all of them were green on 2026-08-16 while the front door was broken for every visitor. G-3 would reflect that eventually, at a resolution of about one event a month; ninety seconds is better.
- **Steward cadence runs `npm run check` FIRST, then reads the overnight CI log.** The two answer different questions and only one is actionable at 07:45: the check says *is the mirror in sync now*, the log says *did the alarm fire overnight and go unnoticed*. Both are needed; the order is not arbitrary. On 2026-08-12 the overnight green log was four and a half hours stale and described a world that no longer existed — worse than no log, because it buys false confidence. Read the log for the **final pushed commit**, never a earlier one (2026-08-11: a close-out verified green *before* its own last push and a red run sat unnoticed for seven hours). **And run the cycle BEFORE dispositioning the day's dated gates** (approved 2026-08-24). On 2026-08-24 that order paid twice by accident: A-2's log entry IS the cycle, and W-7's newly adopted step found both of its first catches inside it. A gate dispositioned before the cycle is dispositioned against a world the cycle is about to change.
- **On an upstream editing burst, resolve once and stop.** Upstream pushed five times on 2026-08-12, three of them rewording one attribution paragraph, and we chased all of it through three resolution cycles in forty minutes. **A burst inflates the drift-cycle count in a way that looks like productivity and is really a measure of upstream's typing speed** — which corrupts the reading of the streak and of the catches-per-week indicator, not just the forty minutes. Rule: after a second consecutive red caused by an upstream push inside an hour, resolve to the latest sha, record the burst, and let the scheduled run be the next check. A red run during a burst is the alarm working; the mirror's contract is byte-fidelity at a **known sha**, not at every instant.
- **Positive control before any absence claim (drift-cycle rule, ruled in 2026-08-12).** Before concluding that a cited artifact lacks something, **name the token you found in the SAME fetch that proves you had the right document.** A positive match is self-validating; "the word is absent" cannot go red on the wrong document, so it checks nothing. See the HTTP-200 gotcha below for the incident this comes from — a prose rule already existed and did not fire, which is why this one is worded as a control with a named output.
- **Gloss the sha CLASS on first use in anything that leaves the repo.** Upstream `teorth/optimizationproblems` shas do not resolve locally: `git cat-file -t 603052d` returns *not a valid object*, and an unglossed arrow chain of them reads to an outside reader as local commits that do not exist — indistinguishable from fabrication until they go looking. Write "(an upstream sha; it does not exist in this repo)" the first time. This bit a retro on 2026-08-12 whose figures were all correct. **Same rule for upstream PATHS, found 2026-08-15 by `check-doc-references.mjs`:** a bare `constants/<name>.md` in our prose is upstream's path, not ours, and resolves to nothing at our HEAD — write the mirrored `ledger/teorth-optimizationproblems/…` form in prose, and keep the bare upstream form only inside file maps and drift reports, where "path as upstream sees it" is the documented key. Note that the first draft of this very rule quoted the bare path as its example and tripped the checker — the note explaining a fix becoming a fresh instance of it is a shape this repo has now hit five times.
- **Snapshot-on-drift discipline.** Treat red `reverify` as the alarm, not a bug: records are supposed to move. Verify the change against **primary sources** before `--snapshot`, then commit the refreshed mirror deliberately; Never snapshot to silence red. **Red is not automatically a record event, and editorial drift is real drift** (2026-07-28: dead cross-link and missing `C` in a LaTeX inequality; no bound moved and pins were byte-identical). The mirror promises byte-fidelity, not only numeric fidelity, so never wave editorial changes through as cosmetic: verify against repo content—the link exists, the corrected inequality is right—and use the same verify → snapshot → re-pin cycle. **The ratchet is THREE steps** (corrected 2026-08-14): snapshot; `node scripts/extract-pins.mjs`, then commit regenerated pins (they never auto-follow, so moved rows remain BROKEN in `check-claims`); and `node scripts/render-state-block.mjs` (README file/claim counts otherwise go STALE). Omitting the third step made `npm run check` exit 1 on 2026-08-14. Use `npm run resnap` (added that day) to run all three in order.
- **Generated pins assert LISTING POSITION, never "the record".** The generated claims pin the LAST-LISTED row of each bounds table verbatim. Do not "upgrade" them to record-row claims: numeric record-ranking is defeated by symbolic cells (`$K_{DR}+10^{-26}$`), negatives, and O(·) asymptotics (a min/max prototype mis-picked 10a/21a/41a on 2026-07-24), and auto-asserting "record" would put unverified mathematical statements in our own ledger. Hand claims (C-1…C-9) may say "record" because a human verified it.
- **Second surface (A-6, adopted 2026-07-25) is ENTRY-LEVEL claims, not a mirror.** `teorth/erdosproblems` (the community metadata DB behind erdosproblems.com, CI-reachable via raw.githubusercontent) is stewarded through pins on specific entries in `teorth/erdosproblems:data/problems.yaml` (C-8 = problem 36), NOT a byte-level mirror: the repo is pushed near-daily, so a whole-file drift alarm would be permanently red — and an always-red alarm carries no information. Pin stable field spans; stop before `last_update` (churns on any edit). The repo takes PRs on the metadata table — an accepted metadata-correction PR is a public dated external ack (G-3), but a PR is outward contact: adversarial review + David's gate, as always. Bounds do NOT live in that repo (verified 2026-07-25) — a bound correction can never be a PR there.
- **Prove the instrument can fail (KP-78).** Ship no detector—test, guard, lint, probe, `--check`, alarm—until it fires with the condition present and stays silent when absent; record both outputs. First prove the mutation landed with `git diff --numstat`: `\n` against CRLF silently no-opped on 2026-07-25. **Test recent commits, not only the test directory:** the 2026-07-31 audit found A-8's CI step had no preserving detector (`docs/findings/2026-07-31-kp78-prove-the-instrument-can-fail.md`, W-4). **2026-08-04: one proven probe does not validate its enumeration.** `gh secret list` missed four GitHub Apps (`vercel`, `render`, `cursor`, `claude`, visible only in `/check-suites`; needs an app-authorized token); ask what a probe can never show (A-13 F-4). **2026-08-17: prove non-firing means the CONDITION is absent, not the INSTRUMENT.** On PowerShell the alarm-title guard resolved `bash` from `PATH`, spawn failed, returned `""`, and an absence assertion passed; assert output exists first. **2026-08-23: an inlined page script is EXECUTED, never pattern-matched.** For `index.html`, `assert.match(html, /appendChild/)` proves only that code shipped. Extract the generated script and run it under `new Function` against a stub DOM; never test a retyped copy (the 2026-08-18 and 2026-08-21 lesson). Export decision logic and keep the in-page half thin. First applied to ordering; four negative controls fired after each mutation was proven to land.
- **The hosted brief drifts from its source, and hand-checking it under-reports.** The orchestrator ports `docs/lane-brief.md` to `/t/lanes/bounds-ledger`. Hand-checks on 7/30 and 7/31 each found ONE primer-named missing block; `check-brief.mjs` (2026-07-31) derived the set and found **two**, stale since 26 July. It runs in `npm run check` and **stays out of CI permanently**: the 7/31 plan to add it after first green was retired 2026-08-03, when the 8/02 sign-in wall showed a runner without `CC_PROMPTS_PIN` exits 3 UNVERIFIABLE. Do not put the pin in repo secrets. This was an old-regime threshold surviving a regime change (A-11 class, 2026-07-31); a stale brief must not consume the LEDGER's goal signal.
- **David-facing prose is linted; which surface decides how.** `node ../skylark-site/scripts/check-david-voice.mjs <file>` (standard: `skylark-site/docs/skylark-voice-standard.md`, adopted 2026-08-03 after David said again that he cannot understand what we write). **`docs/lane-brief.md` is wholly David-facing, so lint the WHOLE file** — the fleet's lint-the-summary-line-never-the-file rule exists because daily reports are repo-facing, and it does not apply here. Daily reports: lint the BLUF line only. **No other document in this repo is voice-linted — that list is exhaustive, not illustrative.** Findings, flow docs, cold-start primers, reconciliations and decision files are all repo-facing, and running the check on one returns exit 3 on whatever em dashes and capitals its previous authors left, which teaches you nothing and costs a round-trip. Written down 2026-08-23 after a run on a flow doc returned 52 pre-existing em dashes; the bullet had simply never said where the scope stopped, so widening it was the reasonable inference. Two carve-outs found on 2026-08-03 in this repo, both reported upstream: `supersedes` is on the jargon list glossed as the bus flag ("replaces an earlier message") and mis-fires on ordinary English about a number; and the check does not exempt blockquotes, so **the verbatim quote of the email David sent on 24 July keeps its em dashes** — that block is a record of an outward artifact, and rewriting it to satisfy a style rule would make the brief misquote what went out. Same instinct as the mirror: byte-fidelity to what was actually sent.

An identifier has at least three surfaces — author fields, tracked files, commit bodies — and a doc is a surface too. **The check that works is ENUMERATE what the repo reveals from a FRESH CLONE OF THE REMOTE; the check that keeps failing is confirm-the-named-defect-is-gone** (`git log --format=%ae` returning one noreply is TRUE and licenses only *no author field carries it*). Enumerate by shape — every email-shaped token, every URL-with-an-id — not by searching for the string you already know about. Never verify a redaction from the working tree.

## Gotchas

- **A feature branch gets ZERO CI runs from pushing — `reverify.yml` declares `push: branches: [main]`.** `gh run list --branch <b>` returning an empty list for a pushed branch is the workflow's configuration, not a missing run, and the branch page looks innocuously blank rather than red. `gh workflow run reverify.yml --ref <branch>` is the only route to a runner verdict. Consequence for holds: **a hold whose release condition has no stated command outlives its reason.** The 8/16 primer said "run it on a Linux runner first" and that read as actionable while the obvious action — push and look — could never have produced a run. When you hold work pending a check, write the command, not the check.
- **Check a held branch can still MERGE before spending a runner on it.** On 2026-08-17 a branch was validated on a runner and returned a clean verdict about code that could never land: `main` had moved and both sides had independently fixed the *same lines* differently, so `git merge-tree --write-tree main <branch>` reported a content conflict. **A runner verdict on an unmergeable sha is a verdict about nothing** — the thing that will actually merge is the conflict resolution, which no run has seen. One command, run first.
- **Do not dispatch `reverify.yml` repeatedly** — each run issues ~450 requests (113 individual raw fetches plus ~110 claim URLs), and the scheduled run is the lane's daily alarm. The first run generally already answered the question; validate a conflict resolution locally rather than with a second dispatch. Since b1 (2026-08-17) a PR gets a run automatically, so there is rarely a reason to dispatch at all. **This is practice guidance, not a diagnosis — read the next bullet before repeating the story that used to be attached to it.**
- **A cause you find flattering to admit still needs a positive control.** This bullet first read "two dispatches inside ten minutes tripped `raw.githubusercontent.com` secondary rate limiting on 2026-08-17". **That was wrong and is retracted.** GitHub was in a *critical outage* from 2026-08-17T13:40:03Z (githubstatus.com incident API, read directly); the first dispatch was 14:32Z, fifty-two minutes later, with Actions already degraded. Three pieces of disconfirming evidence were in hand and unassembled: a local ~450-fetch run was **fully green at 14:28Z**, 48 minutes into the outage; a later *local* check failed although the dispatches were runner-side and share no egress with this machine; and the errors included **502 and 503**, which request volume does not produce. The same self-blame went into a finding, a commit message, `A-5 note4` and two issue comments before any of it was checked. **Self-blame feels like rigour and is just another unverified attribution — and it is the more dangerous kind, because nobody challenges you for blaming yourself.** The repo's existing rule already covered it (positive control before any absence or cause claim); it did not fire because the claim was about our own infrastructure rather than someone else's record. `A-5 note5`.
- **`UNREACHABLE` is not `BROKEN`, and the alarm must never title it as one.** `BROKEN` means the read source lost the pin; `UNREACHABLE` means it was never read. A pure HTTP 429 once titled six records as moved because `UNREACHABLE` matched before the `^error:` branch. **The red stays red**—unreachable is unverified—but only true drift gets a `Drift:` title. Finding: `docs/findings/2026-08-17-the-alarm-called-a-rate-limit-a-record-movement.md`.
- **`gh api .../issues` counts PULL REQUESTS as issues, and the count lags a close by ~10s.** Both bit on 2026-08-17. The first silently inflated an open-issue count the moment two PRs existed — filter `.pull_request == null`. The second returned "1 open" seconds after closing the last one, three times; two consistent reads settle it. Neither is a bug in the alarm, but both feed a figure this lane reports, and a stale read taken immediately after your own mutation is the shape that looks like a real finding.
- **Closing the issue is part of the drift cycle.** Five resolved drifts sat open as `Drift:` issues for up to six days (#10–#14, closed 2026-08-17 naming their resolving commits). Five standing reds teach the next reader that `Drift:` issues can be ignored, which is the precondition for missing a real one — the founding defect in yet another hat. Close on resolution, naming the sha that resolved it.
- **Prove a dangerous command was neutered BEFORE running an extracted body.** The mirror image of "prove the mutation landed": a throwaway one-liner meant to strip `gh issue create` out of a workflow step before executing it had its escaping silently fail, and it filed a real issue against the public repo. The in-repo harness asserts the strip changed the text (`assert.notEqual(harness, raw)`) and refuses to run otherwise; the debug script did not. Any script that executes a step body verbatim asserts the side effect is gone first.
- **A negative control's restore must not be `git checkout --` while the fix is uncommitted.** Restoring the mutated file that way discarded the uncommitted fix being tested, and `npm test` failing was the only reason it surfaced. Commit or stash, then negative-control.
- **`check-brief.mjs` needs `CC_PROMPTS_PIN` in env, or it can see nothing.** Since the 2026-08-02 Supabase wall (skylark-site `53c87f83`), `/t/lanes/*` 307s to an HTTP-200 `/t/signin`; anonymous success is not the brief. The script now proves the source H1, sends `x-cc-pin` from `process.env.CC_PROMPTS_PIN`, and otherwise exits 3 `BRIEF UNVERIFIABLE`. CI logs that and files nothing; an anonymous local run proves nothing. Never put the PIN in repo secrets. Finding: `docs/findings/2026-08-02-the-brief-check-blamed-the-porter-for-a-login-wall.md`.
- **An HTTP 200 is not evidence you fetched the artifact, and a NEGATIVE result from the wrong document is how you publish a false accusation.** On 2026-08-12 preprints.org returned a 2.6 KB bot page (title `&nbsp;`), while ar5iv returned a real 38 KB arXiv abstract page lacking "Jin" instead of the paper. **Before an absence claim, name a token from the SAME fetch proving the artifact**—here even `numerical range` and `spectral set` were absent. For walled papers, Crossref content negotiation (`api.crossref.org/works/<doi>`) supplies title/author/date, enough for citations and priority claims. Finding: `docs/findings/2026-08-12-two-record-movements-in-one-cycle.md`.
- **erdosproblems.com 403s automated fetch — from DATACENTER IPs. The block is IP-dependent.** Residential Node gets HTTP 200; GitHub Actions gets 403. C-7 stays `manual: true` / UNVERIFIED in CI, while local `npm run check` genuinely re-verifies it. **A local 200 proves nothing about CI:** automating C-7 on one made CI red four minutes later on 2026-07-25. Finding: `docs/findings/2026-07-25-the-403-that-wasnt.md`. Do not re-automate from local 200; the only evidence that counts is a green CI run.
- **Test a capability from the environment that will exercise it.** Generalising a laptop result to a runner is how the above happened, and it failed optimistically — the ledger briefly asserted "zero unverified claims" while the claim gating the lane's north-star watch was silently unverifiable in CI.
- **LF→CRLF git warnings on Windows are benign** — ignore them on commit. **But the files on disk really are CRLF**, which has teeth: a Node/regex string replacement written with `\n` (e.g. `s.replace("- name: X\n        shell: bash\n", …)`) **silently no-ops** — no error, no match, and your "edit" never happened. On 2026-07-25 this produced a false INERT verdict on the pipefail guard during the gate sweep: the guard was fine; the negative control hadn't applied. **Always `git diff` to prove a test mutation landed before believing the result.** Use `\r?\n` in patterns.
- **If a guard or shell refuses a documented command, write it VERBATIM to a file and run that file; never paraphrase inline.** On 2026-08-19 a refused README tamper, `node -e "require('node:fs').appendFileSync(…)"`, was retyped as `require('0node:fs')`; `MODULE_NOT_FOUND` left the mirror untouched, then `reverify.mjs --check` falsely printed `No drift.` at exit 0. This is KP-78's silent half: `git diff --numstat` was empty. Use a quoted heredoc (`cat > /tmp/x.sh <<'EOF'`) containing the exact command. After running it, require a non-empty `git diff --numstat` before reading the detector's verdict; an absent mutation makes either answer meaningless. Retyping tests the retyping, not the documented command—the 2026-08-18 lesson.
- **Never write backslashes through a JS string literal into a file; they can disappear SILENTLY** (2026-08-21: one false claim, dead command, and empty code span). The three non-erroring cases were jq `\(...)` in `releaseTest` printing a literal template; an "unedited" README quote retyped as `-C_{71} > 6.5143...` instead of `-C_{71}\ >\ 6.514326913930565372,`; and `` `\ ` `` becoming an empty span. **Do not retype quoted records—extract them.** Pull the commit line with parsed `git show …`, then require `grep -F -x` hits in source and copy plus a fabricated non-match. Reword decorative backslashes away. The first draft of this bullet itself turned escaped em dashes into mojibake: the SIXTH instance of a fix note reproducing its defect; keep the count because the document is inside this silent-corruption class. **"Verbatim" and "unedited" are method claims**: audit them by grepping the source for the quotation and requiring a hit.
- **Never read an exit code through a pipe — locally, not just in CI.** `node scripts/check-claims.mjs --selftest | tail -3` reports *`tail`'s* exit 0 even as the selftest fails. The CI form of this bug is the lane's founding defect (below); the local form bit again during the 2026-07-25 sweep. Redirect to a file and check `$?`, or use `${PIPESTATUS[0]}`.
- **Never pipe a check step in CI without `shell: bash`.** GitHub Actions' default runner shell is `bash -e {0}` — no `pipefail` — so `node scripts/reverify.mjs --check | tee ...` reports `tee`'s exit 0 and a real drift passes green. This made the alarm fake for the lane's first two days (`docs/findings/2026-07-24-drift-alarm-was-never-armed.md`). `reverify.test.mjs` now guards it; don't defeat the guard.
- **After a `--snapshot`, `git status` over-reports — it is not a content diff.** The snapshot rewrites every mirror file, so files whose *content* is unchanged can still show as modified (line-ending / stat-cache artifact). On 2026-07-28 this showed a third changed file the drift report hadn't named, which looks exactly like "our differ under-reports" — a serious charge in this lane. `git diff --numstat` settled it: zero lines changed, differ was right. **Check `--numstat` before believing `git status` disagrees with the drift report.**
- **The clone count in `npm run traffic` is mostly US, and it recurs every single day.** A sample on 2026-08-20 read **154 unique cloner-days against 3 unique viewers** — a ratio that is not an audience. `reverify.yml` checks out the repo on a daily schedule, on every push and on every PR, so the clone figure accrues from our own CI whether or not a human ever arrives. The sampler deliberately does not deduct our own clones, CI checkouts or crawlers and says so in its output; number-provenance rule 2 ("is this number MINE?") applies directly. **The only arrival figure here that is not mostly ours is the viewer count.** Recorded as a known pattern because it is a scheduled-event side-effect that regenerates daily, so every future reader meets it fresh and would otherwise re-investigate it.
- **The mirror diff only sees changes *inside* the adopted repo.** Cross-surface divergence (the lane's founding finding) is caught by `check-claims.mjs`, not `reverify.mjs`. Both run in CI.
