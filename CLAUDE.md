## What this lane is

A **steward** of drifting mathematical records: a reproducible, continuously re-verified ledger that alarms when a cited record (bound / constant / certificate) drifts. Not a record-search engine. Full thesis in `README.md`. Pre-launch.

**Rail: PACED (David-ruled 2026-08-01, effective 2026-08-02; replaces the lite default).** Each session: the steward cadence FIRST (read the overnight run's LOG not the badge; drift cycle if red; local `npm run check` for the W-3 advisory legs), then **≥1 concrete launch increment from A-13's backlog** (first-PR prep, README-as-product, history sweep, adversarial review — the exit is the public flip, tracked as A-13 with the decision proposed to David at streak day 14 = 2026-08-06). **Weekly forced-decision pass** over `continuity/items.json` (stale items move or die). ## Conventions (the load-bearing ones)

- **Curated vs live records: track both, labeled, NEVER blend.** A live/leaderboard claim graduates to the curated column only via a checkable construction or acceptance into a curated source. (Reconciliation #1 finding 3.)
- **A `manual: true` claim reports UNVERIFIED, never green.** When a source blocks automated fetch *from CI* (erdosproblems.com 403s datacenter IPs), the checker cannot re-run it, so it stays UNVERIFIED until a human — or a local `npm run check` — re-verifies. A done-click or hand-verify does not flip it green. That is the "never silently trusted" rule made mechanical, and 2026-07-25 is the argument for keeping it: an attempt to automate C-7 away was caught by CI within minutes precisely because UNVERIFIED-vs-UNREACHABLE is tracked honestly. **A `manual: true` pin on a blocked source is still worth adding** (C-9, 2026-07-26): it reports UNVERIFIED in CI and never touches counts or the exit code, while a local run gets a real advisory read. What failed on 7/25 was making such a pin *fetchable*, not pinning the fact.
- **Steward cadence runs `npm run check` FIRST, then reads the overnight CI log.** The two answer different questions and only one is actionable at 07:45: the check says *is the mirror in sync now*, the log says *did the alarm fire overnight and go unnoticed*. Both are needed; the order is not arbitrary. On 2026-08-12 the overnight green log was four and a half hours stale and described a world that no longer existed — worse than no log, because it buys false confidence. Read the log for the **final pushed commit**, never a earlier one (2026-08-11: a close-out verified green *before* its own last push and a red run sat unnoticed for seven hours).
- **On an upstream editing burst, resolve once and stop.** Upstream pushed five times on 2026-08-12, three of them rewording one attribution paragraph, and we chased all of it through three resolution cycles in forty minutes. **A burst inflates the drift-cycle count in a way that looks like productivity and is really a measure of upstream's typing speed** — which corrupts the reading of the streak and of the catches-per-week indicator, not just the forty minutes. Rule: after a second consecutive red caused by an upstream push inside an hour, resolve to the latest sha, record the burst, and let the scheduled run be the next check. A red run during a burst is the alarm working; the mirror's contract is byte-fidelity at a **known sha**, not at every instant.
- **Positive control before any absence claim (drift-cycle rule, ruled in 2026-08-12).** Before concluding that a cited artifact lacks something, **name the token you found in the SAME fetch that proves you had the right document.** A positive match is self-validating; "the word is absent" cannot go red on the wrong document, so it checks nothing. See the HTTP-200 gotcha below for the incident this comes from — a prose rule already existed and did not fire, which is why this one is worded as a control with a named output.
- **Gloss the sha CLASS on first use in anything that leaves the repo.** Upstream `teorth/optimizationproblems` shas do not resolve locally: `git cat-file -t 603052d` returns *not a valid object*, and an unglossed arrow chain of them reads to an outside reader as local commits that do not exist — indistinguishable from fabrication until they go looking. Write "(an upstream sha; it does not exist in this repo)" the first time. This bit a retro on 2026-08-12 whose figures were all correct.
- **Snapshot-on-drift discipline.** A red `reverify` run is the alarm, not a bug — records are *supposed* to move. Only re-`--snapshot` after verifying the change against **primary sources**, then commit the updated mirror deliberately. Never snapshot just to silence the alarm. **A red run is NOT automatically a record event, and editorial drift is still real drift** (2026-07-28, the first real one: a dead cross-link and a missing `C` in a LaTeX inequality — zero bounds moved, pins regenerated byte-identical). The mirror's contract is byte-fidelity to the adopted surface, not just numeric fidelity, so an editorial change gets the same verify → snapshot → re-pin cycle. Verify it against the repo's own content (does the linked page exist? is the corrected inequality right?) rather than waving it through as cosmetic. **Second step since 2026-07-24:** after every `--snapshot`, re-run `node scripts/extract-pins.mjs` and commit the regenerated pins — pins deliberately do NOT auto-follow the mirror, so a moved table row stays BROKEN in `check-claims` until re-pinned (the post-snapshot ratchet).
- **Generated pins assert listing position, never "the record".** The generated claims pin the LAST-LISTED row of each bounds table verbatim. Do not "upgrade" them to record-row claims: numeric record-ranking is defeated by symbolic cells (`$K_{DR}+10^{-26}$`), negatives, and O(·) asymptotics (a min/max prototype mis-picked 10a/21a/41a on 2026-07-24), and auto-asserting "record" would put unverified mathematical statements in our own ledger. Hand claims (C-1…C-9) may say "record" because a human verified it.
- **Second surface (A-6, adopted 2026-07-25) is ENTRY-LEVEL claims, not a mirror.** `teorth/erdosproblems` (the community metadata DB behind erdosproblems.com, CI-reachable via raw.githubusercontent) is stewarded through pins on specific entries in `teorth/erdosproblems:data/problems.yaml` (C-8 = problem 36), NOT a byte-level mirror: the repo is pushed near-daily, so a whole-file drift alarm would be permanently red — and an always-red alarm carries no information. Pin stable field spans; stop before `last_update` (churns on any edit). The repo takes PRs on the metadata table — an accepted metadata-correction PR is a public dated external ack (G-1), but a PR is outward contact: adversarial review + David's gate, as always. Bounds do NOT live in that repo (verified 2026-07-25) — a bound correction can never be a PR there.
- **Prove the instrument can fail (KP-78).** Ship no detector — test, guard, lint, probe, `--check` mode, alarm — without demonstrating at write time that it returns BOTH answers: it fires when the condition is present, and stays silent when absent (a detector that always fires passes the first assertion while proving nothing). Put both outputs in the finding/commit. Prove the mutation landed with `git diff --numstat` first — a negative control written with `\n` against CRLF files silently no-ops and yields a FALSE inert verdict (that is how the pipefail guard was wrongly pronounced broken on 2026-07-25). **Run this against recent commits, not just the test directory**: the 2026-07-31 audit's most valuable output was a detector that did not exist — A-8's own fix was a hand-added CI step with nothing asserting it stays. `docs/findings/2026-07-31-kp78-prove-the-instrument-can-fail.md`, watch W-4. **Extension, 2026-08-04: proving one probe can fail does NOT validate the enumeration built around it.** I ran `gh secret list` against other repos until it returned non-empty before believing this repo's zero — correct — and then wrote "0 secrets, 0 deploy keys, 1 collaborator" as the answer to "what can reach this repo", which was missing four GitHub Apps (`vercel`, `render`, `cursor`, `claude`, visible only in `/check-suites`, scope unreadable without an app-authorized token). A verified probe licenses its own claim and nothing wider. When the question is "enumerate", the check is not "did my probe fire" but "what would this probe never have shown me" (A-13 F-4).
- **The hosted brief drifts from its source, and hand-checking it under-reports.** `docs/lane-brief.md` is ported to `/t/lanes/bounds-ledger` by the orchestrator, so the page can silently fall behind. It did — and two consecutive hand-checks (7/30, 7/31) each reported ONE missing block because both searched for the block the primer named, instead of deriving the expected set from the source. `check-brief.mjs` (2026-07-31) derives it and found **two** missing, stale since 26 July. Recognition-over-recall applies to our own checks: a hand-check that inherits its search term from a doc can only ever confirm that doc. **Deliberately NOT in the CI drift job** — it would go red and stay red until an orchestrator re-port lands, and a permanently-red alarm carries as much information as a permanently-green one. It runs in `npm run check` and **stays out of CI permanently** — ~~joins CI the run after the page first reads green~~, a pre-commitment written 7/31 that was **retired 2026-08-03, the very day it first fired**. The page read green for the first time that morning, and the clause would have sent the next session to wire a check into CI that CI cannot run: the 8/02 sign-in wall means a runner with no pin exits 3 UNVERIFIABLE, so the only way to satisfy the clause is putting `CC_PROMPTS_PIN` in repo secrets — forbidden with a public flip pending. A threshold derived from the old regime kept reading as authoritative after the regime changed (the A-11 class, 2026-07-31). G-1's streak measures the LEDGER; a stale brief must not consume it.
- **David-facing prose is linted; which surface decides how.** `node ../skylark-site/scripts/check-david-voice.mjs <file>` (standard: `skylark-site/docs/skylark-voice-standard.md`, adopted 2026-08-03 after David said again that he cannot understand what we write). **`docs/lane-brief.md` is wholly David-facing, so lint the WHOLE file** — the fleet's lint-the-summary-line-never-the-file rule exists because daily reports are repo-facing, and it does not apply here. Daily reports: lint the BLUF line only. Two carve-outs found on 2026-08-03 in this repo, both reported upstream: `supersedes` is on the jargon list glossed as the bus flag ("replaces an earlier message") and mis-fires on ordinary English about a number; and the check does not exempt blockquotes, so **the verbatim quote of the email David sent on 24 July keeps its em dashes** — that block is a record of an outward artifact, and rewriting it to satisfy a style rule would make the brief misquote what went out. Same instinct as the mirror: byte-fidelity to what was actually sent.
- **Reviewing what we WROTE is not reviewing what the repo DISCLOSES.** Four artifact-level reviews plus a package-level review all cleared the flip package, and a whole-project pre-publication review (2026-08-05, David's instruction) then returned **eight blockers** and "I would not flip public with this tree and history". None of the earlier five could have caught them, because every one asked "is this artifact accurate?" and none asked "what does this repository reveal about us, our machine, and other people?" The eight were: no `LICENSE` while redistributing 111 mirrored files; an absolute local path in `continuity/health.json`; a doc publishing our own unprotected security posture (which platform-side controls are off); `items.json` publicly describing a portfolio-wide personal-data question belonging to other repos (details held privately — not ours to disclose); a personal author email on every commit; 15 commit bodies carrying private `claude.ai/code/session_…` URLs; and commit `293cec9`, which added a Playwright snapshot of erdosproblems.com containing **third-party forum user handles**. Before any publication, run the disclosure question as its own pass — and note that a decision to accept one disclosure (David's 8/05 accept the history, given about a maintainer's *published* email address) licenses that item and nothing wider.
- **A redaction is done when the STRING is absent from the repository, including from the record of the redaction — and a redaction scoped to one SURFACE leaves the same string on the others.** Four recurrences now, all the same shape: the fix cleans the flagged location and the note explaining the fix becomes a fresh copy. 8/06 the eight-blocker list spelled out the third-party handles and an address *while cataloguing them as things not to publish*; 8/07 the commit written straight after the rewrite re-contaminated from a stale git config; 8/08 the write-up of that put the address back into four files; **8/09 the session-URL sweep was scoped to COMMIT BODIES — which worked, zero — and nobody swept TRACKED FILES, where a complete artifact UUID was sitting in A-13's own note** (`2b751f5`). An identifier has at least three surfaces — author fields, tracked files, commit bodies — and a doc is a surface too. **The check that works is ENUMERATE what the repo reveals from a FRESH CLONE OF THE REMOTE; the check that keeps failing is confirm-the-named-defect-is-gone** (`git log --format=%ae` returning one noreply is TRUE and licenses only *no author field carries it*). Enumerate by shape — every email-shaped token, every URL-with-an-id — not by searching for the string you already know about. Never verify a redaction from the working tree.
- **Never hand David an artifact link.** `claude.ai/code/artifact/...` URLs are session-scoped and do not resolve in his browser — a brief delivered that way reads as page-not-found and the board card gets dismissed (happened 2026-07-24). David-facing briefs for lanes without their own site go on the Skylark site at `/t/lanes/<slug>`: keep the source at `docs/lane-brief.md`, post a bus note, the orchestrator ports it.
- **Audit the method sentence, not just the claim.** Any outward artifact that says "cross-checked against X" must have that sentence verified as its own review angle. On 2026-07-24 a draft claimed cross-checks against "the source-paper abstracts" when none of the three abstracts state their bounds — the phrase was inherited from an earlier, different claim and survived a 5-angle adversarial review because every angle attacked the *value*, not the *method*. A false claim about our own method is the one thing the recipient cannot check.
- **Outward gate.** Any upstream contact (PR, correction, email) or the public-repo flip goes through the **adversarial refute-it review first** (portfolio standing rule), and the actual send is **David-gated**. Never contact a maintainer or flip the repo public on your own. **Extended by David 2026-08-01, as a matter of practice: at least one adversarial review on EVERYTHING this project produces that might touch the public** — not just sends: the flip package, README-as-product, brief blocks, any artifact a stranger could read.
- **No self-rating.** The lane has no self-rating/audit contract (kept under the 2026-08-01 paced-rail ruling). Write the daily report + run the presence linters; skip `/rate-day` scoring (renamed from `/daily-close` on 2026-07-29; a compat shim still answers the old name).

## Gotchas

- **`check-brief.mjs` needs `CC_PROMPTS_PIN` in env, or it can see nothing.** `/t/lanes/*` went behind a Supabase sign-in wall on 2026-08-02 (skylark-site `53c87f83`, intentional, site-wide). The route 307s to `/t/signin` and **the sign-in page returns HTTP 200**, so an anonymous fetch looks successful and every dated block reads "missing" — which is exactly how the checker spent a morning reporting `4 of 4 missing … the port is the orchestrator's` about a page it had never received. The script now proves the response IS the brief (tests for the source's own H1) before assessing staleness, and sends `x-cc-pin` from `process.env.CC_PROMPTS_PIN` when present. **Consequences: CI can never run this check** (no pin on a runner → exit 3 `BRIEF UNVERIFIABLE`, the brief job logs it and deliberately files nothing — a permanently-open issue no action can close is the founding defect again), and **an anonymous local run proves nothing either way**. Only a run with the pin set is evidence. Same shape as C-7. Do NOT "fix" this by putting the PIN in repo secrets — this repo is heading for a public flip. Finding: `docs/findings/2026-08-02-the-brief-check-blamed-the-porter-for-a-login-wall.md`.
- **An HTTP 200 is not evidence you fetched the artifact, and a NEGATIVE result from the wrong document is how you publish a false accusation.** Two cases in one day (2026-08-12): preprints.org returns 200 for a 2.6 KB bot-protection page (title `&nbsp;`), and **ar5iv silently falls back to the arXiv abstract page** — real, relevant, correctly-titled HTML about the right paper. On the strength of "Jin" being absent from that 38 KB fallback I was one step from writing that a mathematician's paper omits an acknowledgement upstream says it makes. **A positive match is self-validating; a negative match proves nothing until you have separately proven you had the right document.** Before concluding a cited source lacks something, name the token from the SAME fetch that proves it is the source — here `numerical range` and `spectral set` were also missing, which for a paper about the numerical range being a spectral set was the tell. The route that worked when the server is walled: **Crossref content negotiation** (`api.crossref.org/works/<doi>`) never touches it and returns title/author/date, enough to verify a citation including a priority claim. Same family as the sign-in wall below and the 403 below that. Finding: `docs/findings/2026-08-12-two-record-movements-in-one-cycle.md`.
- **erdosproblems.com 403s automated fetch — from DATACENTER IPs. The block is IP-dependent.** A plain Node fetch from a residential IP returns **HTTP 200** with the bound readable; the identical fetch from a **GitHub Actions runner returns 403**. So: **CI can never verify C-7** (it stays `manual: true` / UNVERIFIED by design), but **an agent running `npm run check` locally genuinely re-verifies it mechanically** — better than the screenshot round-trip, and available to any local session. **A local 200 proves nothing about CI.** This was established the hard way on 2026-07-25: I tested locally, concluded the constraint was stale, automated C-7, declared "zero UNVERIFIED claims", and CI went red four minutes later. Finding: `docs/findings/2026-07-25-the-403-that-wasnt.md`. **Do not re-automate C-7 on the strength of a local 200 — it has been tried; the only evidence that counts is a green CI run.**
- **Test a capability from the environment that will exercise it.** Generalising a laptop result to a runner is how the above happened, and it failed optimistically — the ledger briefly asserted "zero unverified claims" while the claim gating the lane's north-star watch was silently unverifiable in CI.
- **LF→CRLF git warnings on Windows are benign** — ignore them on commit. **But the files on disk really are CRLF**, which has teeth: a Node/regex string replacement written with `\n` (e.g. `s.replace("- name: X\n        shell: bash\n", …)`) **silently no-ops** — no error, no match, and your "edit" never happened. On 2026-07-25 this produced a false INERT verdict on the pipefail guard during the gate sweep: the guard was fine; the negative control hadn't applied. **Always `git diff` to prove a test mutation landed before believing the result.** Use `\r?\n` in patterns.
- **Never read an exit code through a pipe — locally, not just in CI.** `node scripts/check-claims.mjs --selftest | tail -3` reports *`tail`'s* exit 0 even as the selftest fails. The CI form of this bug is the lane's founding defect (below); the local form bit again during the 2026-07-25 sweep. Redirect to a file and check `$?`, or use `${PIPESTATUS[0]}`.
- **Never pipe a check step in CI without `shell: bash`.** GitHub Actions' default runner shell is `bash -e {0}` — no `pipefail` — so `node scripts/reverify.mjs --check | tee ...` reports `tee`'s exit 0 and a real drift passes green. This made the alarm fake for the lane's first two days (`docs/findings/2026-07-24-drift-alarm-was-never-armed.md`). `reverify.test.mjs` now guards it; don't defeat the guard.
- **After a `--snapshot`, `git status` over-reports — it is not a content diff.** The snapshot rewrites every mirror file, so files whose *content* is unchanged can still show as modified (line-ending / stat-cache artifact). On 2026-07-28 this showed a third changed file the drift report hadn't named, which looks exactly like "our differ under-reports" — a serious charge in this lane. `git diff --numstat` settled it: zero lines changed, differ was right. **Check `--numstat` before believing `git status` disagrees with the drift report.**
- **The mirror diff only sees changes *inside* the adopted repo.** Cross-surface divergence (the lane's founding finding) is caught by `check-claims.mjs`, not `reverify.mjs`. Both run in CI.
