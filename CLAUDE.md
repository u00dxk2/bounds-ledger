## What this lane is

A **steward** of drifting mathematical records: a reproducible, continuously re-verified ledger that alarms when a cited record (bound / constant / certificate) drifts. Not a record-search engine. Full thesis in `README.md`. **LAUNCHED** — David ruled it 2026-08-27; the repo has been public since 2026-08-08.

**Rail: PACED (David-ruled 2026-08-01).** Each session: the steward cadence FIRST (read the overnight run's LOG not the badge; drift cycle if red; local `npm run check` for the W-3 advisory legs), then **≥1 concrete increment on an open goal** — `G-4` (an outside party acts on a watched record WITHOUT us filing the report) is Tier-0. **Weekly forced-decision pass** over `continuity/items.json` (stale items move or die). Still **no self-rating**.

## Conventions (the load-bearing ones)

- **Curated vs live records: track both, labeled, NEVER blend.** A live/leaderboard claim graduates to the curated column only via a checkable construction or acceptance into a curated source. (Reconciliation #1 finding 3.)
- **A `manual: true` claim reports UNVERIFIED, never green.** When a source blocks automated fetch *from CI* (erdosproblems.com 403s datacenter IPs), the checker cannot re-run it, so it stays UNVERIFIED until a human — or a local `npm run check` — re-verifies. A done-click or hand-verify does not flip it green. That is the "never silently trusted" rule made mechanical, and 2026-07-25 is the argument for keeping it: an attempt to automate C-7 away was caught by CI within minutes precisely because UNVERIFIED-vs-UNREACHABLE is tracked honestly. **A `manual: true` pin on a blocked source is still worth adding** (C-9, 2026-07-26): it reports UNVERIFIED in CI and never touches counts or the exit code, while a local run gets a real advisory read. What failed on 7/25 was making such a pin *fetchable*, not pinning the fact.
- **Verify an artifact written FOR an audience from that audience's environment, before review** (endorsed 2026-08-16). Strip author state first: `env -u <VAR>`, fresh clone, no repo-local config. The README's 1-minute check passed only with `CC_PROMPTS_PIN`; `npm run check` exited 3 for every visitor. This is the 2026-07-25 capability/environment rule. **Degenerate case, 2026-08-18: verify a documented command by RUNNING it.** The primer's `git rev-parse --short HEAD origin/main` exited 128 and skipped the cadence; a KP-78 proof licenses only the command it ran, not adjacent lines. `--short=7` also exits 128. Finding: `docs/findings/2026-08-18-the-guard-against-a-wrong-commit-read-never-ran.md`.
- **Read one instrument against its own claim, every session (W-7, decided 2026-08-24 — SHIPPED into the cadence, not deferred again).** Pick ONE script, alarm, counter or `readCommand`; run it; ask what it claims to measure and whether its output could ever have said otherwise. Name it in the day's report in one line opening `W-7 —` (lapsed 09-06 to 09-10; `docs/daily-config.md`). Rotate — never the same one twice running. **Deliberately not a script**: a detector that audits detectors is itself an instrument owing this same question, and every instance so far was a judgment no assertion could have made. Examples: `traffic-snapshot.mjs` printed a threshold retired three days earlier (`137255f`); the dry-week rule read `docs/findings/` after the classification stopped flowing there (`123dd12`); a 90-day filter would have matched all 111 rows because the field existed but did not discriminate; and on 2026-09-02 `returnRate` refused its own first reading because its window boundary was computed rather than read from the source.
- **The visitor path is part of the steward cadence.** Run the README's credential-free check (`node scripts/reverify.mjs --check && node scripts/check-claims.mjs`, then the tamper/restore pair) as its own cadence step. Every other indicator here measures the ledger's internal correctness — drift caught, claims holding, streak days — and all of them were green on 2026-08-16 while the front door was broken for every visitor. G-4 — the Tier-0 goal that an outside party acts on a watched record WITHOUT us filing the report — would reflect that eventually, at a resolution of about one event a month; ninety seconds is better.
- **Steward cadence runs `npm run check` FIRST, then reads the overnight CI log.** The two answer different questions and only one is actionable at 07:45: the check says *is the mirror in sync now*, the log says *did the alarm fire overnight and go unnoticed*. Both are needed; the order is not arbitrary. On 2026-08-12 the overnight green log was four and a half hours stale and described a world that no longer existed — worse than no log, because it buys false confidence. Read the log for the **final pushed commit**, never a earlier one (2026-08-11: a close-out verified green *before* its own last push and a red run sat unnoticed for seven hours). **And run the cycle BEFORE dispositioning the day's dated gates** (approved 2026-08-24). On 2026-08-24 that order paid twice by accident: A-2's log entry IS the cycle, and W-7's newly adopted step found both of its first catches inside it. A gate dispositioned before the cycle is dispositioned against a world the cycle is about to change.
- **On an upstream editing burst, resolve once and stop.** Upstream pushed five times on 2026-08-12, three of them rewording one attribution paragraph, and we chased all of it through three resolution cycles in forty minutes. **A burst inflates the drift-cycle count in a way that looks like productivity and is really a measure of upstream's typing speed** — which corrupts the reading of the streak and of the catches-per-week indicator, not just the forty minutes. Rule: after a second consecutive red caused by an upstream push inside an hour, resolve to the latest sha, record the burst, and let the scheduled run be the next check. A red run during a burst is the alarm working; the mirror's contract is byte-fidelity at a **known sha**, not at every instant.
- **Positive control before any absence claim (drift-cycle rule, ruled in 2026-08-12).** Before concluding that a cited artifact lacks something, **name the token you found in the SAME fetch that proves you had the right document.** A positive match is self-validating; "the word is absent" cannot go red on the wrong document, so it checks nothing. See the HTTP-200 gotcha below for the incident this comes from — a prose rule already existed and did not fire, which is why this one is worded as a control with a named output.
- **A verification note records the command's literal OUTPUT, never a paraphrase of its verdict** (2026-08-25, W-7). `A-18.readCommand` globbed `docs/cold-starts/2026-08-*.md` — the whole month, including twelve primers predating the property — while its documented verdict read "EMPTY means the property held and this item CLOSES". It returned twelve filenames every run, so **its pass condition was unreachable** and a cold agent running it literally would read a held property as failed. The field also carried "Verified 2026-08-24 … grep -L empty", a result that command cannot produce: the verification was real but was run against a week-scoped glob nobody wrote down. **A probe can be run honestly and still record a result its own recorded command cannot produce**, and pasting the actual output plus exit code would have exposed it at the moment it was introduced. Deliberately NOT mechanized into a readCommand-auditor — that contradicts the W-7 ruling that a detector auditing detectors owes the same question.
- **A hand-written statement of a live instrument's value carries an AS-OF and its read command — never a bare present tense** (2026-08-26; a portfolio candidate). A primer opened `CI IS RED AT 4f4d249 … issue #30 is open`; it was true when committed and false seventeen seconds later, when that same commit's push went green. **Why the primer's own convention cannot save it:** later sections supersede earlier ones, but a banner sits ABOVE the append point, so the block the document promotes hardest is the one block that rule cannot reach. Write "as of 22:25Z CI was red at `4f4d249`; release: `check-ci-status.mjs --workflow reverify.yml`". Do NOT retro-edit historical reports — the as-of is what makes them legible rather than false. **The State Appendix is inside this rule for a structural reason (2026-08-30): a report cannot name the commit that lands it.** Write the appendix LAST, from live commands; `docs/daily/2026-08-30-prelaunch.md` is the worked example. **A hand-written state line also expires — give one asserting a live RED its clearing condition** (2026-09-02: a banner said `npm run verify` WILL exit 1 on the brief leg; the orchestrator had ported it overnight and it exited 0. The as-of worked — it said confirm, I confirmed — but nothing told the next writer when to delete the line).
- **Gloss the sha CLASS on first use in anything that leaves the repo.** Upstream `teorth/optimizationproblems` shas do not resolve locally (`git cat-file -t 603052d` → *not a valid object*), so an unglossed chain of them reads to an outsider as local commits that do not exist — indistinguishable from fabrication until they look. Write "(an upstream sha; it does not exist in this repo)" the first time; this bit a retro on 2026-08-12 whose figures were all correct. **Same rule for upstream PATHS** (2026-08-15, caught by `node scripts/sky.mjs check-doc-references.mjs` — it is a FLEET script and does not exist in this lane's `scripts/`; the bare name here cost a P5 run a `MODULE_NOT_FOUND` on 2026-09-05): a bare `constants/<name>.md` in our prose is upstream's path and resolves to nothing at our HEAD — write the mirrored `ledger/teorth-optimizationproblems/…` form in prose, keeping the bare form only inside file maps and drift reports where "path as upstream sees it" is the documented key. The first draft of this very rule tripped the checker on its own example — a fix note becoming a fresh instance of its defect, a shape this repo has now hit SEVEN times — the seventh on 2026-09-10, when a P1 retro named an upstream sha bare INSIDE the sentence reporting that defect, and the agent-status verify-sha gate refused the post twice for it.
- **Snapshot-on-drift discipline.** Treat red `reverify` as the alarm, not a bug: records are supposed to move. Verify the change against **primary sources** before `--snapshot`, then commit the refreshed mirror deliberately. Never snapshot to silence red. **Red is not automatically a record event, and editorial drift is real drift** (2026-07-28: a dead cross-link and a missing `C` in a LaTeX inequality; no bound moved, pins byte-identical). The mirror promises byte-fidelity, not only numeric fidelity, so never wave an editorial change through as cosmetic — verify it against repo content and run the same verify → snapshot → re-pin cycle. **The ratchet is THREE steps** (2026-08-14): `--snapshot`; `extract-pins.mjs` + commit the regenerated pins (they never auto-follow, so moved rows stay BROKEN in `check-claims`); and `render-state-block.mjs` (README counts otherwise go STALE — omitting it made `npm run check` exit 1). Use `npm run resnap` to run all three in order.
- **Generated pins assert LISTING POSITION, never "the record".** The generated claims pin the LAST-LISTED row of each bounds table verbatim. Do not "upgrade" them to record-row claims: numeric record-ranking is defeated by symbolic cells (`$K_{DR}+10^{-26}$`), negatives, and O(·) asymptotics (a min/max prototype mis-picked 10a/21a/41a on 2026-07-24), and auto-asserting "record" would put unverified mathematical statements in our own ledger. Hand claims (C-1…C-9) may say "record" because a human verified it.
- **Second surface (A-6, adopted 2026-07-25) is ENTRY-LEVEL claims, not a mirror.** `teorth/erdosproblems` (the community metadata DB behind erdosproblems.com, CI-reachable via raw.githubusercontent) is stewarded through pins on specific entries in `teorth/erdosproblems:data/problems.yaml` (C-8 = problem 36), NOT a byte-level mirror: the repo is pushed near-daily, so a whole-file drift alarm would be permanently red — and an always-red alarm carries no information. Pin stable field spans; stop before `last_update` (churns on any edit). The repo takes PRs on the metadata table — an accepted metadata-correction PR is a public dated external ack — but note it would NOT satisfy G-4, which forbids a causal path containing an artifact we authored and sent; it is G-3's shape, and G-3 closed 2026-08-26. A PR is outward contact: adversarial review + David's gate, as always. Bounds do NOT live in that repo (verified 2026-07-25) — a bound correction can never be a PR there.
- **Prove the instrument can fail (KP-78).** Ship no detector—test, guard, lint, probe, `--check`, alarm—until it fires with the condition present and stays silent when absent; record both outputs. First prove the mutation landed with `git diff --numstat`: `\n` against CRLF silently no-opped on 2026-07-25. Five ways it has gone wrong, each still live: **test recent commits, not only the test directory** (2026-07-31, `docs/findings/2026-07-31-kp78-prove-the-instrument-can-fail.md`, W-4); **one proven probe does not validate its enumeration** (2026-08-04, `gh secret list` missed four GitHub Apps visible only in `/check-suites` — ask what a probe can never show); **prove non-firing means the CONDITION is absent, not the INSTRUMENT** (2026-08-17, a guard resolved `bash` from `PATH`, spawn failed, returned `""`, and an absence assertion passed — assert output exists first); **an inlined page script is EXECUTED, never pattern-matched** (2026-08-23 — extract the generated script and run it under `new Function` against a stub DOM, never a retyped copy); **a mutation proves the assertion it TRIPPED, not the one you meant** (2026-09-02: a label rewritten to "closed thanks to us" exited 1 on an EQUALITY check and said nothing about the causal guard beside it; only a third mutation, hiding the wording in an `aria-label` where equality cannot see it, exercised that guard); and **ASSERTION ORDER decides which guards are reachable at all** (2026-09-06 — three assertions on one label, an exact-match pin FIRST and two semantic guards after it: every mutation tripped the pin and short-circuited, so "the date must still be disclosed" and "must not say unchanged" were dead code inside the very commit that removed an unsupportable claim. Put the guards that carry the MEANING first and the equality pin LAST, then each mutation names the property it broke instead of only reporting that the string differs. The first red-arm looked like a pass and was the defect).
- **Judge a delegate's diff against the BRANCH it was told to modify, never against `main`** (2026-09-02). Asked to apply two reviewed fixes, Codex REBUILT `fetchWithRetry` instead of editing it — dropping `res.body?.cancel()` and narrowing the transient-code set — and `npm test` passed while the diff against `main` read as a clean feature-plus-fix. A review verdict attaches to an artifact, not to a description of one, so a rebuild silently voids it. **Codex here can edit files and cannot write ANYTHING under `.git/`** (measured, three dispatches; a `tmp/` write probe succeeds): brief it to run NO git command at all and to prove mutations with `grep -c`, never `git diff`; you stage and commit.
- **The hosted brief drifts from its source, and hand-checking it under-reports.** The orchestrator ports `docs/lane-brief.md` to `/t/lanes/bounds-ledger`. Hand-checks on 7/30 and 7/31 each found ONE missing block; `check-brief.mjs` derived the set and found **two**, stale since 26 July. It runs in `npm run check` and **stays out of CI permanently** — a runner without `CC_PROMPTS_PIN` exits 3 UNVERIFIABLE, and the pin does not go in repo secrets. A stale brief must not consume the LEDGER's goal signal.
- **David-facing prose is linted; which surface decides how.** `node scripts/sky.mjs check-david-voice.mjs <file>` (standard: `skylark-site/docs/skylark-voice-standard.md`, adopted 2026-08-03 after David said again that he cannot understand what we write). **`docs/lane-brief.md` is wholly David-facing, so lint the WHOLE file**; daily reports: **the BLUF line only**. **No other document in this repo is voice-linted — that list is exhaustive, not illustrative.** Findings, flow docs, primers, reconciliations and decision files are repo-facing; linting one returns exit 3 on whatever em dashes its authors left, which teaches nothing (2026-08-23: a flow doc returned 52). Two carve-outs, both reported upstream: `supersedes` is on the jargon list and mis-fires on ordinary English; and blockquotes are not exempt, so **the verbatim quote of the email David sent on 24 July keeps its em dashes** — editing a record of what went out to satisfy a style rule would make the brief misquote it.
- **Reviewing what we WROTE is not reviewing what the repo DISCLOSES.** Five reviews cleared the flip package; a whole-project pre-publication review (2026-08-05) then returned **eight blockers** and "I would not flip public with this tree and history". None of the five could have caught them: each asked "is this artifact accurate?", none asked "what does this repository reveal about us, our machine, and other people?" The eight were licensing, local paths, our own security posture, another repo's personal-data question, author emails, session URLs in commit bodies, and third-party forum handles in a committed snapshot. Run the disclosure question as its own pass before any publication; accepting one disclosure licenses that item and nothing wider. Full list: `docs/decisions/2026-08-04-A13-package-adversarial-review.md`.
- **A redaction is done when the STRING is absent from the repository, including from the record of the redaction — and a redaction scoped to one SURFACE leaves the same string on the others.** Four recurrences, one shape: the fix cleans the flagged location and the note explaining it becomes a fresh copy. Sharpest was **8/09 — the session-URL sweep was scoped to COMMIT BODIES (zero hits) and nobody swept TRACKED FILES, where a complete artifact UUID sat in an item note** (`2b751f5`). An identifier has at least three surfaces — author fields, tracked files, commit bodies — and a doc is one too. **The check that works is ENUMERATE what the repo reveals from a FRESH CLONE OF THE REMOTE; the check that keeps failing is confirm-the-named-defect-is-gone** (`git log --format=%ae` returning one noreply is TRUE and licenses only *no author field carries it*). Enumerate by shape — every email-shaped token, every URL-with-an-id — not by searching for the string you already know. Never verify a redaction from the working tree.
- **Never hand David an artifact link.** `claude.ai/code/artifact/...` URLs are session-scoped and do not resolve in his browser — a brief delivered that way reads as page-not-found and the board card gets dismissed (happened 2026-07-24). David-facing briefs for lanes without their own site go on the Skylark site at `/t/lanes/<slug>`: keep the source at `docs/lane-brief.md`, post a bus note, the orchestrator ports it.
- **Audit the method sentence, not just the claim.** Any outward artifact that says "cross-checked against X" must have that sentence verified as its own review angle. On 2026-07-24 a draft claimed cross-checks against "the source-paper abstracts" when none of the three abstracts state their bounds — the phrase was inherited from an earlier, different claim and survived a 5-angle adversarial review because every angle attacked the *value*, not the *method*. A false claim about our own method is the one thing the recipient cannot check. **Twice now** — the second was the Mathstodon draft on 2026-08-13, whose method sentence advertised "231 claims across arXiv, Wikipedia and the erdosproblems metadata DB" when 220 of the 231 are generated pins against the ONE mirrored surface. Four of that review's six amendments landed on that single sentence and none on the rest of the post. Review it as its own angle, every time, and expect it to be where the artifact is wrong.

- **A decision that forbids a channel forbids the CONTENT, not just the form.** David decided NO to a public comment on erdosproblems.com/36 (2026-08-02). The most compelling thing this lane could tell an audience of mathematicians is that a widely-cited index page has shown a superseded bound since January — which is that same comment, delivered somewhere louder. Writing it into a Mathstodon post would have honoured the letter of his no and broken it. The pull toward that content is strong and it will recur, because it is genuinely our best material; the test is not "is this the surface he named" but "is this the thing he declined to say".
- **Outward gate.** Any upstream contact (PR, correction, email) or the public-repo flip goes through the **adversarial refute-it review first** (portfolio standing rule), and the actual send is **David-gated**. Never contact a maintainer or flip the repo public on your own. **Extended by David 2026-08-01, as a matter of practice: at least one adversarial review on EVERYTHING this project produces that might touch the public** — not just sends: the flip package, README-as-product, brief blocks, any artifact a stranger could read.
- **No self-rating.** The lane has no self-rating/audit contract (kept under the 2026-08-01 paced-rail ruling). Write the daily report + run the presence linters; skip `/rate-day` scoring (renamed from `/daily-close` on 2026-07-29; retired 2026-08-03).
- **Daily reports use the canonical H2 set** (adopted 2026-07-25, replacing the old numbered `## (1) …` format): BLUF / What changed / Inputs (controllable) / Outputs (lagging) / Recommendation / On hold pending data / State Appendix — BLUF first, State Appendix present. Lint with `node scripts/sky.mjs check-report-all.mjs docs/daily/<date>-prelaunch.md` (8 linters as of 2026-08-14; expect all clean — don't hard-code the count in your head, the runner prints `N/N`). Adopted rather than waived because a permanently-red linter gets ignored exactly like a permanently-green alarm carries no information — the lane's founding defect, applied to itself. Gloss every tracker ID on first mention per section (`W-3 — the watch on …`); `check-bare-itemids` is strict in the State Appendix.
- **Every daily report classifies the window's findings as record-facing or instrument-facing, in ONE sentence of human judgment — and NEVER as a counter.** Standing from 2026-08-21 (A-23). A counter over `docs/findings/` is inflatable exactly like the self-rating this lane refused to build; the guard is that a human reads the window and nothing counts it. **Why it exists:** `npm run catches` counts drift DETECTION only, so it cannot tell a defect found in the mathematics from one found in our own machinery — and *a lane that only ever finds faults in its own tooling is maintaining itself rather than stewarding records*. **What it decides:** whether adopt-a-second-surface answers a quiet stretch; four instrument-facing findings beside zero movements is a different situation from four record-facing ones, and the dry-week rule treats them identically. Adopting a second surface stays David's call, never self-approved.
  Three clauses the sentence must carry. (1) **Whether a counted catch was numeric or BYTE-ONLY** (2026-08-24): `npm run catches` counts a generated pin whose `expect` changed, and two once changed on one backslash each while no number moved — it reported 2 for a week in which nothing moved. It is honest by construction (its stdout leads with "a CEILING on catches") and must NOT be replaced by a smarter one; numeric parsing of these cells is known-defeated here. The seam it cannot close is a report quoting the bare figure. (2) **The RUNNING COUNT of consecutive instrument-facing days** (2026-08-25) — written by a human, NOT a counter, and the distinction is the point: the dry-week rule fires only on "no movements AND no findings", so a stretch reports "not dry" while every finding in it is about our own machinery. **Do not quote a day-count from THIS file — today's report carries the live one.** (3) **The standing prediction, because a prediction never checked is decoration:** the next record-facing catch is claimed to be a witness-value mismatch on a constant upstream added within ~30 days, found by a human recomputing a cited certificate and by no instrument we run. If one arrives via an alarm, say so and correct the claim.

## Gotchas

Moved to `docs/gotchas.md` 2026-09-18 (context budget; same move `Layout` took on 2026-09-04). **Read it before debugging anything here** — the traps it holds are why several of this lane's alarms exist. Five stay loaded because they govern how you run a command at all:

- **Never read an exit code through a pipe**, in CI or locally — the pipe's exit 0 wins and a real failure passes green. This is the lane's founding defect: the drift alarm was fake for its first two days. CI steps that pipe need `shell: bash`; locally, redirect to a file and read `$?`.
- **ONE command per Bash call, absolute paths.** A compound, a pipe, a `$VAR` or a relative path can park this machine's permission classifier at a silent prompt that is indistinguishable from a hang. Anything compound goes through the PowerShell tool; file reads go through Read/Grep/Glob.
- **`UNREACHABLE` is not `BROKEN`.** BROKEN means the source was read and the pinned string is gone (a record moved); UNREACHABLE means it was never read. The run goes red either way, but only true drift gets a `Drift:` title.
- **Never kill a node process by name, by age, or because it looks orphaned** — the process table is shared by every pane on this machine. Only a PID from your own pidfile, or one whose command line names this repo.
- **Never run `doppler` in any form** — it prints its token into the transcript, and this lane does not use it.
