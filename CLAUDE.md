## What this lane is

A **steward** of drifting mathematical records: a reproducible, continuously re-verified ledger that alarms when a cited record (bound / constant / certificate) drifts. Not a record-search engine. Full thesis in `README.md`. **LAUNCHED** — David ruled it 2026-08-27; the repo has been public since 2026-08-08.

**Rail: PACED (David-ruled 2026-08-01).** Each session: the steward cadence FIRST (read the overnight run's LOG not the badge; drift cycle if red; local `npm run check` for the W-3 advisory legs), then **≥1 concrete increment on an open goal** — `G-4` (an outside party acts on a watched record WITHOUT us filing the report) is Tier-0. **Weekly forced-decision pass** over `continuity/items.json` (stale items move or die). Still **no self-rating**.

## Conventions (the load-bearing ones)

- **Curated vs live records: track both, labeled, NEVER blend.** A live/leaderboard claim graduates to the curated column only via a checkable construction or acceptance into a curated source. (Reconciliation #1 finding 3.)
- **A `manual: true` claim reports UNVERIFIED, never green.** When a source blocks automated fetch *from CI* (erdosproblems.com 403s datacenter IPs), the checker cannot re-run it, so it stays UNVERIFIED until a human — or a local `npm run check` — re-verifies. A done-click or hand-verify does not flip it green. That is the "never silently trusted" rule made mechanical, and 2026-07-25 is the argument for keeping it: an attempt to automate C-7 away was caught by CI within minutes precisely because UNVERIFIED-vs-UNREACHABLE is tracked honestly. **A `manual: true` pin on a blocked source is still worth adding** (C-9, 2026-07-26): it reports UNVERIFIED in CI and never touches counts or the exit code, while a local run gets a real advisory read. What failed on 7/25 was making such a pin *fetchable*, not pinning the fact.
- **Verify an artifact written FOR an audience from that audience's environment, before review** (endorsed 2026-08-16). Strip author state first: `env -u <VAR>`, fresh clone, no repo-local config. The README's 1-minute check passed only with `CC_PROMPTS_PIN`; `npm run check` exited 3 for every visitor. This is the 2026-07-25 capability/environment rule. **Degenerate case, 2026-08-18: verify a documented command by RUNNING it.** The primer's `git rev-parse --short HEAD origin/main` exited 128 and skipped the cadence; a KP-78 proof licenses only the command it ran, not adjacent lines. `--short=7` also exits 128. Finding: `docs/findings/2026-08-18-the-guard-against-a-wrong-commit-read-never-ran.md`.
- **Read one instrument against its own claim, every session (W-7, decided 2026-08-24 — SHIPPED into the cadence, not deferred again).** Pick ONE script, alarm, counter or `readCommand`; run it; ask what it claims to measure and whether its output could ever have said otherwise. Name it in the day's report in one line. Rotate — never the same one twice running. **Deliberately not a script**: a detector that audits detectors is itself an instrument owing this same question, and every instance so far was a judgment no assertion could have made. Five in ten days — `traffic-snapshot.mjs` printed a threshold retired three days earlier (`137255f`); the dry-week rule read `docs/findings/` after the classification had stopped flowing there (`123dd12`); `G-3.readCommand` was blind to a detection path we had just built; a 90-day filter would have matched all 111 rows because the field existed but did not discriminate; and the drift job auto-closes its own issue naming no resolving sha, so a reader learns that it ended and not how (2026-08-24, #29 — commented by hand).
- **The visitor path is part of the steward cadence.** Run the README's credential-free check (`node scripts/reverify.mjs --check && node scripts/check-claims.mjs`, then the tamper/restore pair) as its own cadence step. Every other indicator here measures the ledger's internal correctness — drift caught, claims holding, streak days — and all of them were green on 2026-08-16 while the front door was broken for every visitor. G-4 — the Tier-0 goal that an outside party acts on a watched record WITHOUT us filing the report — would reflect that eventually, at a resolution of about one event a month; ninety seconds is better.
- **Steward cadence runs `npm run check` FIRST, then reads the overnight CI log.** The two answer different questions and only one is actionable at 07:45: the check says *is the mirror in sync now*, the log says *did the alarm fire overnight and go unnoticed*. Both are needed; the order is not arbitrary. On 2026-08-12 the overnight green log was four and a half hours stale and described a world that no longer existed — worse than no log, because it buys false confidence. Read the log for the **final pushed commit**, never a earlier one (2026-08-11: a close-out verified green *before* its own last push and a red run sat unnoticed for seven hours). **And run the cycle BEFORE dispositioning the day's dated gates** (approved 2026-08-24). On 2026-08-24 that order paid twice by accident: A-2's log entry IS the cycle, and W-7's newly adopted step found both of its first catches inside it. A gate dispositioned before the cycle is dispositioned against a world the cycle is about to change.
- **On an upstream editing burst, resolve once and stop.** Upstream pushed five times on 2026-08-12, three of them rewording one attribution paragraph, and we chased all of it through three resolution cycles in forty minutes. **A burst inflates the drift-cycle count in a way that looks like productivity and is really a measure of upstream's typing speed** — which corrupts the reading of the streak and of the catches-per-week indicator, not just the forty minutes. Rule: after a second consecutive red caused by an upstream push inside an hour, resolve to the latest sha, record the burst, and let the scheduled run be the next check. A red run during a burst is the alarm working; the mirror's contract is byte-fidelity at a **known sha**, not at every instant.
- **Positive control before any absence claim (drift-cycle rule, ruled in 2026-08-12).** Before concluding that a cited artifact lacks something, **name the token you found in the SAME fetch that proves you had the right document.** A positive match is self-validating; "the word is absent" cannot go red on the wrong document, so it checks nothing. See the HTTP-200 gotcha below for the incident this comes from — a prose rule already existed and did not fire, which is why this one is worded as a control with a named output.
- **A verification note records the command's literal OUTPUT, never a paraphrase of its verdict** (2026-08-25, W-7). `A-18.readCommand` globbed `docs/cold-starts/2026-08-*.md` — the whole month, including twelve primers predating the property — while its documented verdict read "EMPTY means the property held and this item CLOSES". It returned twelve filenames every run, so **its pass condition was unreachable** and a cold agent running it literally would read a held property as failed. The field also carried "Verified 2026-08-24 … grep -L empty", a result that command cannot produce: the verification was real but was run against a week-scoped glob nobody wrote down. **A probe can be run honestly and still record a result its own recorded command cannot produce**, and pasting the actual output plus exit code would have exposed it at the moment it was introduced. Deliberately NOT mechanized into a readCommand-auditor — that contradicts the W-7 ruling that a detector auditing detectors owes the same question.
- **A hand-written statement of a live instrument's value carries an AS-OF and its read command — never a bare present tense** (2026-08-26; a portfolio candidate). A primer opened `CI IS RED AT 4f4d249 … issue #30 is open`. It was **true when committed** and false **seventeen seconds later**, when the push of that same commit produced a green run; the issue closed two minutes after that. Same day, same shape, twice more. **Why the primer's own convention cannot save it:** later sections supersede earlier ones, but a banner sits ABOVE the append point, so the block the document promotes hardest is the one block that rule cannot reach. Write "as of 22:25Z CI was red at `4f4d249`; release: `node ../skylark-site/scripts/check-ci-status.mjs --workflow reverify.yml`". Do NOT retro-edit historical reports — they were true as of their write time, and the as-of is exactly what makes that legible instead of looking like a lie.
- **Gloss the sha CLASS on first use in anything that leaves the repo.** Upstream `teorth/optimizationproblems` shas do not resolve locally (`git cat-file -t 603052d` → *not a valid object*), so an unglossed chain of them reads to an outsider as local commits that do not exist — indistinguishable from fabrication until they look. Write "(an upstream sha; it does not exist in this repo)" the first time; this bit a retro on 2026-08-12 whose figures were all correct. **Same rule for upstream PATHS** (2026-08-15, caught by `check-doc-references.mjs`): a bare `constants/<name>.md` in our prose is upstream's path and resolves to nothing at our HEAD — write the mirrored `ledger/teorth-optimizationproblems/…` form in prose, keeping the bare form only inside file maps and drift reports where "path as upstream sees it" is the documented key. The first draft of this very rule tripped the checker on its own example — a fix note becoming a fresh instance of its defect, a shape this repo has now hit six times.
- **Snapshot-on-drift discipline.** Treat red `reverify` as the alarm, not a bug: records are supposed to move. Verify the change against **primary sources** before `--snapshot`, then commit the refreshed mirror deliberately. Never snapshot to silence red. **Red is not automatically a record event, and editorial drift is real drift** (2026-07-28: a dead cross-link and a missing `C` in a LaTeX inequality; no bound moved, pins byte-identical). The mirror promises byte-fidelity, not only numeric fidelity, so never wave an editorial change through as cosmetic — verify it against repo content and run the same verify → snapshot → re-pin cycle. **The ratchet is THREE steps** (2026-08-14): `--snapshot`; `extract-pins.mjs` + commit the regenerated pins (they never auto-follow, so moved rows stay BROKEN in `check-claims`); and `render-state-block.mjs` (README counts otherwise go STALE — omitting it made `npm run check` exit 1). Use `npm run resnap` to run all three in order.
- **Generated pins assert LISTING POSITION, never "the record".** The generated claims pin the LAST-LISTED row of each bounds table verbatim. Do not "upgrade" them to record-row claims: numeric record-ranking is defeated by symbolic cells (`$K_{DR}+10^{-26}$`), negatives, and O(·) asymptotics (a min/max prototype mis-picked 10a/21a/41a on 2026-07-24), and auto-asserting "record" would put unverified mathematical statements in our own ledger. Hand claims (C-1…C-9) may say "record" because a human verified it.
- **Second surface (A-6, adopted 2026-07-25) is ENTRY-LEVEL claims, not a mirror.** `teorth/erdosproblems` (the community metadata DB behind erdosproblems.com, CI-reachable via raw.githubusercontent) is stewarded through pins on specific entries in `teorth/erdosproblems:data/problems.yaml` (C-8 = problem 36), NOT a byte-level mirror: the repo is pushed near-daily, so a whole-file drift alarm would be permanently red — and an always-red alarm carries no information. Pin stable field spans; stop before `last_update` (churns on any edit). The repo takes PRs on the metadata table — an accepted metadata-correction PR is a public dated external ack — but note it would NOT satisfy G-4, which forbids a causal path containing an artifact we authored and sent; it is G-3's shape, and G-3 closed 2026-08-26. A PR is outward contact: adversarial review + David's gate, as always. Bounds do NOT live in that repo (verified 2026-07-25) — a bound correction can never be a PR there.
- **Prove the instrument can fail (KP-78).** Ship no detector—test, guard, lint, probe, `--check`, alarm—until it fires with the condition present and stays silent when absent; record both outputs. First prove the mutation landed with `git diff --numstat`: `\n` against CRLF silently no-opped on 2026-07-25. Four ways it has gone wrong, each still live: **test recent commits, not only the test directory** (2026-07-31, A-8's CI step had no preserving detector — `docs/findings/2026-07-31-kp78-prove-the-instrument-can-fail.md`, W-4); **one proven probe does not validate its enumeration** (2026-08-04, `gh secret list` missed four GitHub Apps visible only in `/check-suites` — ask what a probe can never show); **prove non-firing means the CONDITION is absent, not the INSTRUMENT** (2026-08-17, a guard resolved `bash` from `PATH`, spawn failed, returned `""`, and an absence assertion passed — assert output exists first); **an inlined page script is EXECUTED, never pattern-matched** (2026-08-23, `assert.match(html, /appendChild/)` proves only that code shipped — extract the generated script and run it under `new Function` against a stub DOM, and never test a retyped copy).
- **The hosted brief drifts from its source, and hand-checking it under-reports.** The orchestrator ports `docs/lane-brief.md` to `/t/lanes/bounds-ledger`. Hand-checks on 7/30 and 7/31 each found ONE primer-named missing block; `check-brief.mjs` (2026-07-31) derived the set and found **two**, stale since 26 July. It runs in `npm run check` and **stays out of CI permanently**: the 7/31 plan to add it after first green was retired 2026-08-03, when the 8/02 sign-in wall showed a runner without `CC_PROMPTS_PIN` exits 3 UNVERIFIABLE. Do not put the pin in repo secrets. This was an old-regime threshold surviving a regime change (A-11 class, 2026-07-31); a stale brief must not consume the LEDGER's goal signal.
- **David-facing prose is linted; which surface decides how.** `node ../skylark-site/scripts/check-david-voice.mjs <file>` (standard: `skylark-site/docs/skylark-voice-standard.md`, adopted 2026-08-03 after David said again that he cannot understand what we write). **`docs/lane-brief.md` is wholly David-facing, so lint the WHOLE file**; daily reports: **the BLUF line only**. **No other document in this repo is voice-linted — that list is exhaustive, not illustrative.** Findings, flow docs, primers, reconciliations and decision files are repo-facing, and linting one returns exit 3 on whatever em dashes its previous authors left, which teaches nothing and costs a round-trip (written down 2026-08-23 after a flow doc returned 52). Two carve-outs, both reported upstream: `supersedes` is on the jargon list glossed as the bus flag and mis-fires on ordinary English; and the check does not exempt blockquotes, so **the verbatim quote of the email David sent on 24 July keeps its em dashes** — rewriting a record of what went out to satisfy a style rule would make the brief misquote it. Same instinct as the mirror: byte-fidelity to what was actually sent.
- **Reviewing what we WROTE is not reviewing what the repo DISCLOSES.** Four artifact-level reviews plus a package-level review all cleared the flip package; a whole-project pre-publication review (2026-08-05, David's instruction) then returned **eight blockers** and "I would not flip public with this tree and history". None of the five could have caught them: every one asked "is this artifact accurate?" and none asked "what does this repository reveal about us, our machine, and other people?" The eight, by shape: a missing `LICENSE` while redistributing mirrored files; an absolute local path in a tracked JSON; a doc publishing our own unprotected security posture; the ledger describing another repo's personal-data question; a personal author email on every commit; 15 commit bodies carrying private session URLs; and a committed page snapshot containing **third-party forum handles**. Run the disclosure question as its own pass before any publication — and note that accepting one disclosure (David's 8/05 accept-the-history, about a maintainer's *published* address) licenses that item and nothing wider. Full list: `docs/decisions/2026-08-04-A13-package-adversarial-review.md`.
- **A redaction is done when the STRING is absent from the repository, including from the record of the redaction — and a redaction scoped to one SURFACE leaves the same string on the others.** Four recurrences, all one shape: the fix cleans the flagged location and the note explaining the fix becomes a fresh copy. The sharpest was **8/09 — the session-URL sweep was scoped to COMMIT BODIES, which worked (zero), and nobody swept TRACKED FILES, where a complete artifact UUID sat in an item note** (`2b751f5`). An identifier has at least three surfaces — author fields, tracked files, commit bodies — and a doc is a surface too. **The check that works is ENUMERATE what the repo reveals from a FRESH CLONE OF THE REMOTE; the check that keeps failing is confirm-the-named-defect-is-gone** (`git log --format=%ae` returning one noreply is TRUE and licenses only *no author field carries it*). Enumerate by shape — every email-shaped token, every URL-with-an-id — not by searching for the string you already know. Never verify a redaction from the working tree.
- **Never hand David an artifact link.** `claude.ai/code/artifact/...` URLs are session-scoped and do not resolve in his browser — a brief delivered that way reads as page-not-found and the board card gets dismissed (happened 2026-07-24). David-facing briefs for lanes without their own site go on the Skylark site at `/t/lanes/<slug>`: keep the source at `docs/lane-brief.md`, post a bus note, the orchestrator ports it.
- **Audit the method sentence, not just the claim.** Any outward artifact that says "cross-checked against X" must have that sentence verified as its own review angle. On 2026-07-24 a draft claimed cross-checks against "the source-paper abstracts" when none of the three abstracts state their bounds — the phrase was inherited from an earlier, different claim and survived a 5-angle adversarial review because every angle attacked the *value*, not the *method*. A false claim about our own method is the one thing the recipient cannot check. **Twice now** — the second was the Mathstodon draft on 2026-08-13, whose method sentence advertised "231 claims across arXiv, Wikipedia and the erdosproblems metadata DB" when 220 of the 231 are generated pins against the ONE mirrored surface. Four of that review's six amendments landed on that single sentence and none on the rest of the post. Review it as its own angle, every time, and expect it to be where the artifact is wrong.

- **A decision that forbids a channel forbids the CONTENT, not just the form.** David decided NO to a public comment on erdosproblems.com/36 (2026-08-02). The most compelling thing this lane could tell an audience of mathematicians is that a widely-cited index page has shown a superseded bound since January — which is that same comment, delivered somewhere louder. Writing it into a Mathstodon post would have honoured the letter of his no and broken it. The pull toward that content is strong and it will recur, because it is genuinely our best material; the test is not "is this the surface he named" but "is this the thing he declined to say".
- **Outward gate.** Any upstream contact (PR, correction, email) or the public-repo flip goes through the **adversarial refute-it review first** (portfolio standing rule), and the actual send is **David-gated**. Never contact a maintainer or flip the repo public on your own. **Extended by David 2026-08-01, as a matter of practice: at least one adversarial review on EVERYTHING this project produces that might touch the public** — not just sends: the flip package, README-as-product, brief blocks, any artifact a stranger could read.
- **No self-rating.** The lane has no self-rating/audit contract (kept under the 2026-08-01 paced-rail ruling). Write the daily report + run the presence linters; skip `/rate-day` scoring (renamed from `/daily-close` on 2026-07-29; retired 2026-08-03).
- **Daily reports use the canonical H2 set** (adopted 2026-07-25, replacing the old numbered `## (1) …` format): BLUF / What changed / Inputs (controllable) / Outputs (lagging) / Recommendation / On hold pending data / State Appendix — BLUF first, State Appendix present. Lint with `node ../skylark-site/scripts/check-report-all.mjs docs/daily/<date>-prelaunch.md` (8 linters as of 2026-08-14; expect all clean — don't hard-code the count in your head, the runner prints `N/N`). Adopted rather than waived because a permanently-red linter gets ignored exactly like a permanently-green alarm carries no information — the lane's founding defect, applied to itself. Gloss every tracker ID on first mention per section (`W-3 — the watch on …`); `check-bare-itemids` is strict in the State Appendix.
- **Every daily report classifies the window's findings as record-facing or instrument-facing, in ONE sentence of human judgment — and NEVER as a counter.** Standing from 2026-08-21 (A-23). A counter over `docs/findings/` is inflatable exactly like the self-rating this lane refused to build; the guard is that a human reads the window and nothing counts it. **Why it exists:** `npm run catches` counts drift DETECTION only, so it cannot tell a defect found in the mathematics from one found in our own machinery — and *a lane that only ever finds faults in its own tooling is maintaining itself rather than stewarding records*. **What it decides:** whether adopt-a-second-surface answers a quiet stretch; four instrument-facing findings beside zero movements is a different situation from four record-facing ones, and the dry-week rule treats them identically. Adopting a second surface stays David's call, never self-approved.
  Three clauses the sentence must carry. (1) **Whether a counted catch was numeric or BYTE-ONLY** (2026-08-24): `npm run catches` counts a generated pin whose `expect` changed, and that day two changed on one backslash each while no number moved anywhere — it reported 2 for a week in which nothing was recorded as moving. The counter is honest by construction (its stdout leads with "a CEILING on catches, not a count of them") and must NOT be replaced by a smarter one; numeric parsing of these cells is known-defeated here. The seam it cannot close is a report or bus line quoting the bare figure. (2) **The RUNNING COUNT of consecutive instrument-facing days** (2026-08-25) — a number a human writes into the sentence, NOT a counter, and the distinction is the point. It exists because the dry-week rule fires only on "no movements AND no findings", so a stretch with both reports "not dry" while every finding in it is about our own machinery. **Do not quote a day-count from THIS file — it is stale by construction; today's report carries the live one.** (3) **The standing prediction, because a prediction never checked is decoration:** the next record-facing catch is claimed to be a witness-value mismatch on a constant upstream added within ~30 days, flagged by a human recomputing a cited certificate and by no instrument we run. If one arrives via an alarm instead, say so and correct the claim.
- **MT for human labels** (commits, file slugs, doc headers, `docs/cold-starts/<MT-date>.md`); UTC only for cross-system timestamps (bus, git `%ai`, logs).

## Layout

- `continuity/items.json` — the item ledger (IDs: `G-` goal, `A-` active, `W-` watch). The source of truth for what's open.
- `continuity/traffic.json` — accumulated GitHub traffic samples (W-6). Append-only in effect; the API forgets days older than 14, so this file is the only copy of anything before the current window. Refresh with `npm run traffic` during the steward cadence.
- `docs/reconciliations/` — resolved record discrepancies (the lane's method template lives in #1).
- `docs/findings/` — smaller verified catches.
- `docs/decisions/` — filed decisions awaiting a gate (e.g. A-3's report-upstream draft).
- `docs/daily/<date>-prelaunch.md` — daily reports (needs §3a YAML frontmatter — the r8 linter FAILs without it). **The `-prelaunch` suffix is a HISTORICAL FILENAME, not a lifecycle claim, and is deliberately NOT being renamed** (2026-08-27): David ruled this lane LAUNCHED that day and `lifecycle_stage: launched` is in the frontmatter, but 35+ committed files and every cross-reference point at this path, and the fleet's `REPORT_CONFIGS` resolves to exactly it — renaming buys a tidier name and costs a day of dead references. Read the suffix as "where the reports have always lived"; the frontmatter is the authority on stage. Labelled rather than chased, which is the cheaper fix for a stale-looking label on a changed state.
- `docs/cold-starts/<MT-date>.md` — next-agent primer.
- `docs/lane-brief.md` — **source** for the David-facing brief hosted at `https://skylarkcreations.com/t/lanes/bounds-ledger`. Edit here, then post a bus note so the orchestrator re-ports it.
- `ledger/teorth-optimizationproblems/` — machine **mirror** of the adopted surface: every `constants/*.md` file **plus the repo-root `README.md`** (W-5, 2026-08-10) + `manifest.json` pinning the upstream sha. The count grows when upstream adds a constant; `--check` prints the live figure, so don't write one here. **Why the README is in scope:** the constants files carry the bound tables, but the README is where upstream declares which rows it will STAND BEHIND — a demotion to asterisked-unverified leaves every table byte-identical, so mirroring `constants/**` alone was blind to it (upstream `dee1660`, 2026-08-02: our alarm named three constants files and was silent on the semantically largest change of the day). File maps are keyed by **path as upstream sees it** — the README at the root, each constants file under its own `constants/` prefix. **Do not hand-edit**; refresh only via `--snapshot`.
- `ledger/claims.json` — claim-level value pins (source URL + exact expected string per claim). 11 hand claims (C-1…C-11; C-10 and C-11 are the `nothingAfter` negative pins added 2026-08-11 by A-11, on Wikipedia and `teorth/erdosproblems` respectively; C-8 pins problem 36's entry in `teorth/erdosproblems:data/problems.yaml` — the A-6 second surface; **C-7 + C-9 are the two `manual: true` claims, both on erdosproblems.com/36** — C-7 the bound, C-9 the `last edited 23 January 2026` string) + generated pins (`pin:<file>:U|L`, `generated: true`) covering every constant — 220 across 110 files as of 2026-08-01 (1b.md stays hand-pinned), and the count moves whenever upstream adds a constant. Hand-edit only the hand claims; generated pins are rewritten wholesale by `extract-pins.mjs`.
- `scripts/` — `reverify.mjs` (mirror diff), `check-claims.mjs` (cross-surface claims), `extract-pins.mjs` (regenerates generated pins), `render-state-block.mjs` (**generates README's committed "Current state"; never hand-edit it**; records file count, upstream sha and claim inventory, never a stale live verdict), `check-brief.mjs` (hosted-brief drift; needs the pin), `history-sweep.mjs` (no-secrets gate), `gap-table.mjs` (G-2 ranker; asserts nothing mathematical), `traffic-snapshot.mjs` (W-6 arrival sampler; renders no verdict). Command list and gate wiring live in `AGENTS.md` — do not duplicate them here.
  `check-deferrals.mjs` (A-25) — a deferral carries `deferral: true`, an `expiresOn` and a runnable `releaseTest`. `check-self-attribution.mjs` — a self-attributed CAUSE carries `control:` on the same line, naming what would show the cause is NOT ours; its trigger list is MEASURED against this repo's corpus, and it fires on blame pointed at US while staying silent on blame pointed at upstream — deliberately asymmetric, because nobody challenges you for blaming yourself. Both are wired in `AGENTS.md`; do not restate their wiring here.
  `catch-rate.mjs` — a catch is a GENERATED pin whose `expect` changed; count DISTINCT records per week, never movements. **Positive counts are an UPPER BOUND / activity ceiling; zero is exact.** Quote PER-WEEK, never the running total. A month of zeros means adopt a second surface — David's call, never self-approved; the script header carries the full 2026-08-14 derivation.
  `*.test.mjs` / `--selftest` are network-free and CI-wired; `reverify.test.mjs` prints the live count and fails if a new one lacks a workflow step.
- `search/27b/` — G-2 contribution harness for the Earth-Moon target: `verifier.mjs` (exact DMP planarity + exact chromatic number + certificate check — the DUMB half; model proposes, this code disposes), `selftest.mjs`, `find-sulanke-partition.mjs` + `sulanke-certificate.json` (the reproduced 1980 record — proof the harness can score the known answer), and the search rounds `propose-round.mjs` (r1, propose-then-test) / `round2-grow.mjs` (r2, biplanar by construction) / `round3-seeded.mjs` (r3, edge-budget family scan + growth from a held seed). Certificates are the product; never weaken the verifier to make a candidate pass. **A budget/elimination gate must be proven silent on the record itself** — a gate that flagged Sulanke's own graph would close a family by arithmetic error and every conclusion drawn from it would be worthless (round three).

## Gotchas

- **NEVER run `doppler configure` or `doppler whoami` in any form — they PRINT the CLI token into the transcript** (fleet rule, effective 2026-08-27, after `doppler configure --json` leaked one into a lane transcript today). This lane does not use Doppler at all and has no reason to invoke it; the line is here so a future agent reaching for a generic secrets-CLI habit stops. Credentials on this machine come from user-scope env at run time (see the global CLAUDE.md § Secrets), and the standing rule that a `catch` block in scope of a secret prints a FIXED STRING applies to any such call. **Blast radius framing, not urgency theatre:** a value in a session transcript is a local + API-log exposure, not a public disclosure, and the right response is a controlled rotation, never an emergency delete that breaks work in flight.
- **NEVER kill a node process by NAME, by AGE, or because it "looks orphaned" — the process table on this machine is shared by all 24 panes** (fleet rule, 2026-08-27). `Get-Process node` lists every lane's bus listener, loop-death waker, dev server and vitest worker, not yours. Measured, not cautionary: three lane-side sweeps in one afternoon killed node processes machine-wide, one "reaped 43 orphans" that were other lanes' live listeners, and every listener but one died in the same second. **Only two permitted kill shapes:** (1) a PID you own, read from YOUR pidfile (`tmp/.bus-listen.pid`) or a job record you wrote; (2) a process whose COMMAND LINE contains this lane's repo path — `Get-CimInstance Win32_Process -Filter "name='node.exe'" | Where-Object { $_.CommandLine -match 'bounds-ledger' }` — never a bare `Get-Process node`. Suspect a stray? Post its PID and command line on the bus and LEAVE IT ALONE; the orchestrator holds the fleet-wide census. **It is here although we caused none of it, because the failure mode is diagnostic:** we were the VICTIM, our waker exited `127` and our listener died, and the honest first reading — "my relaunch is broken" — was wrong. Same shape as the 2026-08-17 rate-limit retraction: a cause flattering to admit is still an unverified attribution.
- **A feature branch gets ZERO CI runs from pushing — `reverify.yml` declares `push: branches: [main]`.** `gh run list --branch <b>` returning an empty list for a pushed branch is the workflow's configuration, not a missing run, and the branch page looks innocuously blank rather than red. `gh workflow run reverify.yml --ref <branch>` is the only route to a runner verdict. Consequence for holds: **a hold whose release condition has no stated command outlives its reason.** The 8/16 primer said "run it on a Linux runner first" and that read as actionable while the obvious action — push and look — could never have produced a run. When you hold work pending a check, write the command, not the check.
- **Check a held branch can still MERGE before spending a runner on it.** On 2026-08-17 a branch was validated on a runner and returned a clean verdict about code that could never land: `main` had moved and both sides had independently fixed the *same lines* differently, so `git merge-tree --write-tree main <branch>` reported a content conflict. **A runner verdict on an unmergeable sha is a verdict about nothing** — the thing that will actually merge is the conflict resolution, which no run has seen. One command, run first.
- **Do not dispatch `reverify.yml` repeatedly** — each run issues ~450 requests (113 individual raw fetches plus ~110 claim URLs), and the scheduled run is the lane's daily alarm. The first run generally already answered the question; validate a conflict resolution locally rather than with a second dispatch. Since b1 (2026-08-17) a PR gets a run automatically, so there is rarely a reason to dispatch at all. **This is practice guidance, not a diagnosis — read the next bullet before repeating the story that used to be attached to it.**
- **A cause you find flattering to admit still needs a positive control.** This bullet first blamed our own dispatch volume for tripping `raw.githubusercontent.com` rate limiting on 2026-08-17. **That was wrong and is retracted:** GitHub was in a *critical outage* from 13:40:03Z (githubstatus.com incident API), and the first dispatch was 52 minutes later with Actions already degraded. Three pieces of disconfirming evidence were in hand and unassembled — a local ~450-fetch run fully green 48 minutes into the outage; a later *local* check failing although the dispatches were runner-side and share no egress with this machine; and errors including **502 and 503**, which request volume does not produce. The self-blame reached a finding, a commit message, an item note and two issue comments before any of it was checked. **Self-blame feels like rigour and is just another unverified attribution — the more dangerous kind, because nobody challenges you for blaming yourself.** The existing positive-control rule did not fire because the claim was about our own infrastructure rather than someone else's record. `A-5 note5`.
- **A FAILED RUN IS NOT A FAILED CHECK — read the JOB layer** (2026-08-26). `check-ci-status`, `gh run list` and the badge all read the run-level `conclusion`, and during a GitHub Actions outage that field was wrong in BOTH directions on this repo inside four minutes: `8a35eaf` reported `completed/failure` with both jobs `queued` and **zero steps executed** (a RED where nothing ran, and no `Drift:` issue because the filing step never ran), while `1cb3f65` reported `startup_failure` over a `check` job that was `completed/success` with **29 of 29 steps**, drift and claims legs included. Read `gh api repos/OWNER/REPO/actions/jobs/<id>` before treating either as a verdict; positive control that the endpoint reports real conclusions is a settled run (`c25cecd` → `completed/success`, 29 and 7 steps). This is the CI-layer twin of the invariant below, and the same discipline: **a check that never ran is UNVERIFIED, not passed and not failed.**
- **`UNREACHABLE` is not `BROKEN`, and the alarm must never title it as one.** `BROKEN` means the read source lost the pin; `UNREACHABLE` means it was never read. A pure HTTP 429 once titled six records as moved because `UNREACHABLE` matched before the `^error:` branch. **The red stays red**—unreachable is unverified—but only true drift gets a `Drift:` title. Finding: `docs/findings/2026-08-17-the-alarm-called-a-rate-limit-a-record-movement.md`.
- **`gh api .../issues` counts PULL REQUESTS as issues, and the count lags a close by ~10s.** Both bit on 2026-08-17. The first silently inflated an open-issue count the moment two PRs existed — filter `.pull_request == null`. The second returned "1 open" seconds after closing the last one, three times; two consistent reads settle it. Neither is a bug in the alarm, but both feed a figure this lane reports, and a stale read taken immediately after your own mutation is the shape that looks like a real finding.
- **Closing the issue is part of the drift cycle.** Five resolved drifts sat open as `Drift:` issues for up to six days (#10–#14, closed 2026-08-17 naming their resolving commits). Five standing reds teach the next reader that `Drift:` issues can be ignored, which is the precondition for missing a real one — the founding defect in yet another hat. Close on resolution, naming the sha that resolved it.
- **Prove a dangerous command was neutered BEFORE running an extracted body.** The mirror image of "prove the mutation landed": a throwaway one-liner meant to strip `gh issue create` out of a workflow step before executing it had its escaping silently fail, and it filed a real issue against the public repo. The in-repo harness asserts the strip changed the text (`assert.notEqual(harness, raw)`) and refuses to run otherwise; the debug script did not. Any script that executes a step body verbatim asserts the side effect is gone first.
- **A negative control's restore must not be `git checkout --` while the fix is uncommitted.** Restoring the mutated file that way discarded the uncommitted fix being tested, and `npm test` failing was the only reason it surfaced. Commit or stash, then negative-control.
- **`check-brief.mjs` needs `CC_PROMPTS_PIN` in env, or it can see nothing.** Since the 2026-08-02 Supabase wall (skylark-site `53c87f83`), `/t/lanes/*` 307s to an HTTP-200 `/t/signin`; anonymous success is not the brief. The script now proves the source H1, sends `x-cc-pin` from `process.env.CC_PROMPTS_PIN`, and otherwise exits 3 `BRIEF UNVERIFIABLE`. CI logs that and files nothing; an anonymous local run proves nothing. Never put the PIN in repo secrets. Finding: `docs/findings/2026-08-02-the-brief-check-blamed-the-porter-for-a-login-wall.md`.
- **An HTTP 200 is not evidence you fetched the artifact, and a NEGATIVE result from the wrong document is how you publish a false accusation.** On 2026-08-12 preprints.org returned a 2.6 KB bot page (title `&nbsp;`), while ar5iv returned a real 38 KB arXiv abstract page lacking "Jin" instead of the paper. **Before an absence claim, name a token from the SAME fetch proving the artifact**—here even `numerical range` and `spectral set` were absent. For walled papers, Crossref content negotiation (`api.crossref.org/works/<doi>`) supplies title/author/date, enough for citations and priority claims. Finding: `docs/findings/2026-08-12-two-record-movements-in-one-cycle.md`.
- **erdosproblems.com 403s automated fetch — from DATACENTER IPs, so the block is IP-dependent, and this is why you test a capability from the environment that will EXERCISE it.** Residential Node gets HTTP 200; GitHub Actions gets 403. `C-7` stays `manual: true` / UNVERIFIED in CI while a local `npm run check` genuinely re-verifies it. **A local 200 proves nothing about CI:** automating `C-7` on the strength of one made CI red four minutes later (2026-07-25, `docs/findings/2026-07-25-the-403-that-wasnt.md`). Generalising a laptop result to a runner failed OPTIMISTICALLY — the ledger briefly asserted "zero unverified claims" while the claim gating its north-star watch was silently unverifiable in CI. The only evidence that counts is a green CI run.
- **LF→CRLF git warnings on Windows are benign** — ignore them on commit. **But the files on disk really are CRLF**, which has teeth: a Node/regex string replacement written with `\n` (e.g. `s.replace("- name: X\n        shell: bash\n", …)`) **silently no-ops** — no error, no match, and your "edit" never happened. On 2026-07-25 this produced a false INERT verdict on the pipefail guard during the gate sweep: the guard was fine; the negative control hadn't applied. **Always `git diff` to prove a test mutation landed before believing the result.** Use `\r?\n` in patterns.
- **If a guard or shell refuses a documented command, write it VERBATIM to a file and run that file; never paraphrase inline.** On 2026-08-19 a refused README tamper, `node -e "require('node:fs').appendFileSync(…)"`, was retyped as `require('0node:fs')`; `MODULE_NOT_FOUND` left the mirror untouched, then `reverify.mjs --check` falsely printed `No drift.` at exit 0. This is KP-78's silent half: `git diff --numstat` was empty. Use a quoted heredoc (`cat > /tmp/x.sh <<'EOF'`) containing the exact command. After running it, require a non-empty `git diff --numstat` before reading the detector's verdict; an absent mutation makes either answer meaningless. Retyping tests the retyping, not the documented command—the 2026-08-18 lesson.
- **Never write backslashes through a JS string literal into a file; they can disappear SILENTLY** (2026-08-21: one false claim, dead command, and empty code span). The three non-erroring cases were jq `\(...)` in `releaseTest` printing a literal template; an "unedited" README quote retyped as `-C_{71} > 6.5143...` instead of `-C_{71}\ >\ 6.514326913930565372,`; and `` `\ ` `` becoming an empty span. **Do not retype quoted records—extract them.** Pull the commit line with parsed `git show …`, then require `grep -F -x` hits in source and copy plus a fabricated non-match. Reword decorative backslashes away. The first draft of this bullet itself turned escaped em dashes into mojibake: the SIXTH instance of a fix note reproducing its defect; keep the count because the document is inside this silent-corruption class. **"Verbatim" and "unedited" are method claims**: audit them by grepping the source for the quotation and requiring a hit.
- **Never read an exit code through a pipe — in CI and locally, and this is the lane's founding defect.** GitHub Actions' default runner shell is `bash -e {0}` with no `pipefail`, so `node scripts/reverify.mjs --check | tee ...` reports `tee`'s exit 0 and a real drift passes green: the alarm was fake for this repo's first two days (`docs/findings/2026-07-24-drift-alarm-was-never-armed.md`). CI steps that pipe need `shell: bash`, and `reverify.test.mjs` guards it — do not defeat the guard. The LOCAL form bit again during the 2026-07-25 sweep: `node scripts/check-claims.mjs --selftest | tail -3` reports *`tail`'s* exit 0 while the selftest fails. Redirect to a file and check `$?`, or use `${PIPESTATUS[0]}`.
- **After a `--snapshot`, `git status` over-reports — it is not a content diff.** The snapshot rewrites every mirror file, so files whose *content* is unchanged can still show as modified (line-ending / stat-cache artifact). On 2026-07-28 this showed a third changed file the drift report hadn't named, which looks exactly like "our differ under-reports" — a serious charge in this lane. `git diff --numstat` settled it: zero lines changed, differ was right. **Check `--numstat` before believing `git status` disagrees with the drift report.**
- **The clone count in `npm run traffic` is mostly US, and it recurs every single day.** A sample on 2026-08-20 read **154 unique cloner-days against 3 unique viewers** — a ratio that is not an audience. `reverify.yml` checks out the repo on a daily schedule, on every push and on every PR, so the clone figure accrues from our own CI whether or not a human ever arrives. The sampler deliberately does not deduct our own clones, CI checkouts or crawlers and says so in its output; number-provenance rule 2 ("is this number MINE?") applies directly. **The only arrival figure here that is not mostly ours is the viewer count.** Recorded as a known pattern because it is a scheduled-event side-effect that regenerates daily, so every future reader meets it fresh and would otherwise re-investigate it.
- **The mirror diff only sees changes *inside* the adopted repo.** Cross-surface divergence (the lane's founding finding) is caught by `check-claims.mjs`, not `reverify.mjs`. Both run in CI.
